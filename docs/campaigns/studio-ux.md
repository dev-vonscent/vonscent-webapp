## 0. Товч

Код ажиллаж байгаа ч админ талын UX хэрэглэхэд хэцүү: арга хэмжээ ба hero **хоёр тусдаа хуудсанд**,
хоёулаа **хажуугийн самбар (drawer)** дотор, текстүүд нь «Жижиг гарчиг», «Каталогийн гарчиг»,
«Утасны богино тайлбар» гэх мэт **нэртэй input-ийн урт жагсаалт**. Админ аль талбар дэлгүүрийн
хаана гарахыг мэдэхгүй, холбоосыг гараар (slug, `tags=new&gender=male`) бичнэ.

Шийдэл — **«Арга хэмжээний студи»**: нэг арга хэмжээг эхнээс нь дуустал нэг **бүтэн хуудсанд**, 5 алхмаар хийнэ.

```
① Үндсэн  →  ② Бараа, хямдрал  →  ③ Каталогт харагдах  →  ④ Нүүрний баннер  →  ⑤ Шалгаад нийтлэх
```

Гурван гол дүрэм:

1. **Нэг арга хэмжээ = нэг урсгал.** Баннер (hero) нь арга хэмжээний нэг алхам. Хугацаа, холбоос, нэр
   нь арга хэмжээнээс автоматаар ирнэ; эхлэхэд баннер солигдож, дуусахад өмнөх баннер руу өөрөө буцна.
2. **Текстийг харагдах газар дээр нь засна.** Маягтын талбар биш — дэлгүүрт гарах яг тэр харагдац
   (баннер, каталогийн хэсэг) дээр бэлэн текстүүд гарч ирнэ; дарж байгаад шууд бичнэ.
3. **Кодын үг байхгүй.** «slug», «hero», «badge», «priority», query string админд харагдахгүй.
   Холбоосыг жагсаалтаас сонгоно; өгөгдмөл нь «энэ арга хэмжээний бараанууд».
4. **Арга хэмжээгүй үед улирлын 4 баннер.** Хавар / Зун / Намар / Өвлийн баннерыг нэг удаа бэлдээд орхино;
   улирал эхлэхэд өөрөө солигдоно. Арга хэмжээ эхлэхэд түүний баннер дээгүүр гарч, дуусахад **тэр мөчийн
   улирлын** баннер буцаж гарна (D9).
5. **Зөвхөн үнэртнийг нь солих.** Баннерын зураг дээрх 3 үнэртнийг DB-ээс сонгож сольж болно — дэвсгэр,
   чимэглэл, текст хэвээр (D10).

## 3. Шийдвэрүүд

### D1. Бүтэн хуудас, drawer биш

- `/admin/sale-events` — жагсаалт (§4.1).
- `/admin/sale-events/new`, `/admin/sale-events/[id]` — **студи**. Админы sidebar хэвээр (чиг баримжаа),
  гэхдээ агуулгын хэсэг бүтэн өргөнөөр.
- `FormDrawer`-ийг арга хэмжээ, hero хоёрт **хэрэглэхгүй**.

### D2. 5 алхам — шинэ үед дарааллаар, засах үед чөлөөтэй

| # | Алхам | Юу хийх | Заавал уу |
|---|-------|---------|-----------|
| ① | Үндсэн | Нэр, эхлэх/дуусах өдөр. Холбоос автоматаар | Тийм — үүнгүйгээр цааш явахгүй |
| ② | Бараа, хямдрал | Бараа сонгох, хэмжээ бүрт хувь (одоогийн `ItemsSection`) | Нийтлэхэд ≥1 бараа |
| ③ | Каталогт харагдах | Каталогийн жишээ харагдац дээр chip, гарчиг, тайлбар, тэмдэг, тоолуур | Үгүй — өгөгдмөл нь бэлэн |
| ④ | Нүүрний баннер | Зураг (AI / оруулах) → баннер дээр текст, товчоо засах | Үгүй — «Баннергүй» байж болно |
| ⑤ | Шалгаад нийтлэх | Юу болохын тойм, дутуу зүйлс, «Нийтлэх» | — |

- Шинэ арга хэмжээ: ①-ийг бөглөөгүй бол бусад алхам идэвхгүй (ноорог мөр үүсгэхэд нэр, хугацаа хэрэгтэй).
  ①-ээс цааш бүх алхам **чөлөөтэй** — дараалал нь санал, түгжээ биш.
- Алхам бүр stepper дээр төлөвтэй: ✓ бэлэн · ● одоо · ○ хийгээгүй · ! анхаарах зүйлтэй.
- Засах үед сүүлд байсан алхам биш, **⑤ Шалгах** дээр нээгдэнэ (тойм + үсрэх холбоосууд) — зөвхөн ноорог нь дутуу бол эхний дутуу алхам дээр.
- Алхмыг URL-д `?step=catalog` гэж хадгална, гэхдээ **`window.history.replaceState`**-ээр (серверийн render
  өдөөхгүй). Тиймээс stepper-ийн сонгогдсон төлөвт CLAUDE.md-ийн «`transition-colors` хэрэглэхгүй» дүрэм
  зөрчигдөхгүй; сонгогдсон алхам `bg-cta text-cta-foreground`.

### D3. Нүүрний баннерын текстийг баннер дээр нь засна

- Зураг сонгосны (эсвэл сонгохоос **өмнө** — жишээ зурган дээр) дараа жинхэнэ `CampaignHero` том харагдана,
  **бэлэн текстүүдтэй** (§6.2). Текст бүр дээр хулгана очиход нимгэн хүрээ + нэрийн шошго («Гарчиг»);
  дарахад яг тэр газраа бичигдэнэ; хажууд нь жижиг тоологч («23/48»).
- Товч дээр дарахад: бичгийг нь газар дээр нь засна + доор нь жижиг цонх «Дарахад хаашаа очих вэ?» (D5).
- Хоосон сонголтот хэсгүүд бүдэг «+ Жижиг гарчиг нэмэх», «+ Хоёр дахь товч нэмэх» гэж харагдана.
- Дээд талд **«Компьютер | Утас»** сэлгэгч. Утасны харагдац дээр тайлбарыг засвал `mobileDescription`
  бичигдэнэ, компьютер дээр засвал `description`. «Тайлбар (desktop)» / «Утасны богино тайлбар» гэсэн хоёр
  талбарын ялгааг админ **харж** ойлгоно — нэрээр нь биш.
- Маягтын `CountedInput`-ууд **устана**. Баннерын доор ямар ч текстийн input байхгүй.

### D4. Каталогийн текстийг каталогийн жишээ харагдац дээр засна

- ③-р алхамд каталогийн хуудасны **жижигрүүлсэн, жинхэнэ төрхтэй хэсэг** гарна: шүүлтүүрийн chip-ийн мөр,
  арга хэмжээний зурвас (`SaleEventBanner`-ийн төрх), ②-т сонгосон эхний 4 бараа тэмдэг, хямдарсан үнэтэйгээ.
- Засагдах цэг бүр дугаартай (①–⑤) ба доор нь тайлбарын жагсаалт (§5.3). Дарж засна — D3-тай ижил механизм.
- Тэмдгийг нэг картан дээр засахад бүх карт зэрэг солигдоно («нэг тэмдэг бүх бараанд» гэдгийг харуулна).

### D5. Холбоос автоматаар; сонгохдоо хүний хэлээр

- ①-д нэр бичихэд холбоос (slug) **автоматаар** үүснэ. Харагдац: `vonscent.mn/sale/black-friday` гэсэн
  саарал мөр + «Хуулах» + «Өөрчлөх» (дарвал л input болно). «slug» гэдэг үг UI-д байхгүй — **«Холбоос»**.
- Баннерын үндсэн товч өгөгдмөлөөр **энэ арга хэмжээ** рүү (`{type:"event", slug}`) заана. Админ юу ч хийхгүй.
  ①-д холбоосоо өөрчилбөл товчны зорилт дагаж солигдоно (хадгалах үед ноорог дахь slug-аар дахин бичнэ).
- «Хаашаа очих вэ?» сонголт (товч бүрт):

  | Сонголт (админд харагдах) | Хадгалагдах `HeroTarget` |
  |---|---|
  | **Энэ арга хэмжээний бараанууд** (санал болгосон) | `{type:"event", slug:<энэ>}` |
  | Бүх каталог | `{type:"path", href:"/catalog"}` |
  | Улирлын үнэртэн → Хавар / Зун / Намар / Өвөл | `{type:"season", value}` |
  | Шинэ бараа | `{type:"catalog", query:"tags=new"}` |
  | Багц үүсгэх | `{type:"path", href:"/collections/build"}` |
  | Бэлгийн карт | `{type:"path", href:"/gift-cards"}` |
  | Өөр хуудас… (нарийн) | `{type:"path", href}` — input, `/`-ээр эхэлсэн дотоод хаяг |

  Жагсаалтыг `src/lib/constants.ts`-д `HERO_LINK_PRESETS` болгож хадгална (label + target). Тугийн ард
  байгаа хуудас (бэлгийн карт г.м.) нь туг хаалттай бол жагсаалтад гарахгүй. «Каталогийн шүүлт»-ийн
  түүхий query input зөвхөн «Өөр хуудас… (нарийн)» дотор үлдэнэ. `HeroTarget`-ийн төрөл, DB check **өөрчлөгдөхгүй**.
- Өөр арга хэмжээ рүү заах сонголтыг студид **харуулахгүй** (fixes.md F2-ийн «эхлээгүй арга хэмжээ рүү
  заасан hero гарахгүй» урхинд админ орохгүй). Тусгай өдрийн ба улирлын баннерын засварт (§7) хэвээр үлдэнэ.

### D6. Баннер нь арга хэмжээний хэсэг — хугацаа, нийтлэлт нэг

- Студид үүссэн баннер = `heroes` мөр, `sale_event_id = <арга хэмжээ>`. Хугацаа нь арга хэмжээнээс уншигдана
  (0182-ын одоогийн зан төлөв). Арга хэмжээ эхлэхэд гарна, дуусахад / зогсооход унтарч, нүүр хуудас
  дараагийн баннер руу (тусгай өдрийн баннер → **улирлын баннер** (D9) → кодын нөөц) **өөрөө** буцна —
  `resolveHomeHero()` + `live_heroes()` аль хэдийн «эхний тохирох нь» гэж ажилладаг; D9 нь улирлыг тэр жагсаалтад нэмнэ.
- Баннерт **тусдаа «Нийтлэх» байхгүй.** Баннер бүрэн (хоёр зураг + гарчиг + товчны бичиг) бол `is_active = true`
  гэж хадгална; дутуу бол `false` ба ⑤-д «Баннер дутуу: утасны зураг» гэж гарна. Дэлгүүрт гарах эсэхийг
  арга хэмжээний нийтлэлт + хугацаа шийднэ (`live_heroes()`-ийн одоогийн дүрэм).
- Админаас нуух талбарууд ба өгөгдмөл:

  | Талбар | Студид |
  |---|---|
  | `name` (дотоод нэр) | = арга хэмжээний нэр (≤60), автоматаар |
  | `priority` | `HERO_EVENT_PRIORITY = 10` (constants) — тусгай өдрийн баннераас (0) дээгүүр; улирлын баннер үргэлж хамгийн доор (D9) |
  | `starts_at` / `ends_at` | null (арга хэмжээнээс) |
  | `image_alt` | өгөгдмөл «{нэр} — нүүрний баннер»; зургийн самбарын «Нэмэлт» дотор засна |
  | `dark` | зургаас автоматаар (`suggestDark`); баннерын дээд мөрөнд «Текстийн өнгө: Бараан / Цагаан» |

- Студи нэг арга хэмжээнд **нэг** баннер удирдана (`sale_event_id`-тай, хамгийн сүүлд шинэчлэгдсэн мөр).
  DB олон мөрийг зөвшөөрдөг хэвээр; хэрэв хуучин өгөгдөлд хоёр байвал ④-т «Энэ арга хэмжээнд өөр 1 баннер
  холбоотой байна» гэсэн мөр + «Нүүрний баннер» хуудас руу холбоос.
- ⑤-р алхам хугацааны шугамаар **юу болохыг** бичнэ (§5.5) — A7-гийн хариу.

### D7. Хадгалалт — төлөвөөс хамаарна, үргэлж харагдана

| Арга хэмжээний төлөв | Хадгалалт |
|---|---|
| **Ноорог** | Алхам солих бүрт, мөн inline засвар дууссанаас 2 секундийн дараа **автоматаар** (дэлгүүрт нөлөөгүй тул аюулгүй). Толгойд «Хадгалагдлаа · 14:02» / «Хадгалж байна…» / «Хадгалагдсангүй — дахин оролдох» |
| **Товлосон**, **Явж байна** | Автомат хадгалалт **байхгүй**. Өөрчлөлт гармагц доод талд наалдсан мөр: «Хадгалаагүй өөрчлөлт · [Болих] [Хадгалах]». Явж буйд одоогийн «Одоо дэлгүүрт шууд нөлөөлнө» баталгаажуулалт хэвээр |
| **Дууссан** | Засахгүй (fixes.md F1). Студи уншихаар нээгдэнэ + «Хуулж шинээр эхлүүлэх» |

- Шинэ арга хэмжээ: ①-ийн «Үргэлжлүүлэх» дээр ноорог мөр үүснэ (`POST`), URL `/admin/sale-events/<id>?step=products` болно.
- Хадгалах дараалал: **арга хэмжээ → баннер** (хоёр хүсэлт, одоогийн route-ууд). Баннер нь арга хэмжээний
  id, slug-аас хамаарна. Арга хэмжээ хадгалагдаад баннер унавал: ④-р алхам «!» болж, алдааг тэнд харуулна;
  арга хэмжээ хүчинтэй хэвээр (баннер заавал биш). Шинэ RPC хэрэггүй.
- Хадгалаагүй өөрчлөлттэй гарах гэвэл баталгаажуулна (`beforeunload` + студийн доторх холбоосууд дээр `useConfirm`).

### D9. Улирлын 4 баннер — нэг удаа бэлдэнэ, өөрөө эргэлдэнэ

**Давхарга (дээрээс доош, эхний тохирох нь гарна):**

```
1. Арга хэмжээний баннер      — арга хэмжээ явж байх хугацаанд (студийн ④)
2. Тусгай өдрийн баннер       — хямдралгүй, огноотой (жишээ: Halloween 10/26–10/31)
3. Улирлын баннер             — Хавар / Зун / Намар / Өвөл, үргэлж нэг нь
4. Кодын нөөц                 — DB хоосон / алдаа / туг хаалттай (одоогийн HOME_CAMPAIGNS, EVERGREEN_HERO)
```

- Улирлын баннер = `heroes` мөр, шинэ `season` баганатай (`spring|summer|autumn|winter`), улирал бүрт **ганц** мөр.
  Огноо, арга хэмжээ, эрэмбэгүй. **Он байхгүй** — жил бүр өөрөө давтагдана, дахин үүсгэх шаардлагагүй.
- Улирал бүр зөвхөн **эхлэх өдөртэй** (`season_start_md`, сар-өдөр). Дуусах өдөр гэж байхгүй — дараагийн улирал
  эхлэх хүртэл гарна. Дүрэм: *бэлэн (идэвхтэй, зурагтай) улирлын баннеруудаас эхлэх өдөр нь өнөөдрөөс (УБ)
  хойшгүй хамгийн сүүлийнх; жилийн эхэнд ийм нь байхгүй бол хамгийн сүүлд эхэлдэг нь (өмнөх оноос үргэлжилнэ)*.
  Ингэснээр завсар, давхцал **гарах боломжгүй**; нэг улирлын зураг бэлэн биш бол өмнөх улирлынх үргэлжилнэ.
- Өгөгдмөл эхлэх өдөр: Хавар **3/1**, Зун **6/1**, Намар **9/1**, Өвөл **12/1** (`SEASON_HERO_STARTS`, constants).
  Админ улирлын картан дээр «Эхлэх өдөр»-ийг сар/өдрөөр өөрчилж болно (Монголд өвөл эрт эхэлдэг — §13 Q4).
- Арга хэмжээ дуусах мөчид тусгай логик **хэрэггүй**: арга хэмжээний баннер жагсаалтаас гарахад тэр мөчийн
  улирал нь өөрөө үлдэнэ. Жишээ: 11/23–12/3 арга хэмжээ → эхлэхэд Намрын баннер байсан, дуусахад **Өвлийн**
  баннер гарна. Студийн ⑤-р алхам яг аль нь гарахыг нэрээр нь бичнэ (`heroAt`).
- Өгөгдмөл текст, холбоос (улирал бүрт, админ canvas дээр засна):

  | | Өгөгдмөл |
  |---|---|
  | Дээд мөр | Энэ улирлын сонголт |
  | Гарчиг | Хаврын / Зуны / Намрын / Өвлийн тансаг үнэртнүүд |
  | Гол товч | «Өвлийн үнэртэн» → `{type:"season", value:"winter"}` (тухайн улирал) |
  | Нэмэлт товч | «Бүх үнэртэн» → `/catalog` |

- Анхны өгөгдөл: одоо кодод байгаа зургуудыг (`public/hero-desktop-winter-*`, `hero-desktop-v4-*`) storage руу
  хуулж мөр үүсгэх **script** (`scripts/seed-season-heroes.ts`, migration биш — CLAUDE.md). Өвөл = одоогийн
  өвлийн зураг, Намар = одоогийн үндсэн (v4) зураг; Хавар, Зун хоосон — админ AI-аар (сэдэв `spring`, `summer`
  нь `HERO_THEMES`-д бий) эсвэл зураг оруулж бэлдэнэ. Хоосон улирлыг өмнөх нь нөхнө.
- Амьд гарч буй улирлын баннерыг засахад D7-ийн «явж байна» дүрэм: автомат хадгалалтгүй, «Одоо нүүр хуудсанд
  шууд солигдоно» баталгаажуулалт.

### D10. Зөвхөн үнэртнийг нь солих

- Баннер бүр (улирлын, арга хэмжээний, тусгай өдрийн) дээр гарч буй үнэртнүүдээ **мэднэ**: `heroes.product_ids`
  (ихдээ 3, дараалал = зүүн / төв / баруун). Canvas-ийн доор: «Баннер дээрх үнэртэн: Layton · Aventus · The Most Wanted».
- Canvas дээр зургийн үнэртний хэсэгт (баруун тал) hover хийхэд **«Үнэртэн солих»** товч — текстийг дарж
  засдагтай ижил зарчим (D3). Улирлын картан дээр мөн адил товч.
- Урсгал:
  1. 3 суудал (Зүүн / Төв / Баруун) — одоогийн үнэртнүүдээр бөглөгдсөн. Суудал дээр дарж DB-ээс хайж сонгоно
     (`useProductOptions`); зураггүй барааг сонгох боломжгүй («Энэ бараанд зураг алга»).
  2. **[Үнэртнийг солих]** → 1–2 минут. Энэ хооронд хуудаснаас гарч болно.
  3. Үр дүн **«Өмнө | Дараа»** зэрэгцүүлж (эсвэл гулсуулагчаар) харагдана. Админ: «Ашиглах» / «Дахин оролдох» / «Болих».
  4. «Ашиглах» → компьютерын зураг солигдоно; утасны зургийг шинэ компьютерын зургаас үүсгэх алхам (одоогийн
     «утасны хувилбар» урсгал) **шууд** санал болгогдоно — хоёр зураг ижил үнэртэнтэй байх ёстой. Хоёулаа
     бэлэн болтол хуучин хос дэлгүүрт хэвээр (хагас солигдсон төлөв гарахгүй): шинэ хос нь ноорог төлөвт
     хадгалагдаж, «Хадгалах» дээр хамт солигдоно.
  5. Текст, товч, холбоос, хуваарь **хөндөгдөхгүй**. `image_alt` үнэртний нэрсээр автоматаар шинэчлэгдэнэ
     («Layton, Aventus, … болон decant савнууд»).
- **Техник:** одоогийн AI урсгал үнэртэн оруулахдаа «лавлах дүр зураг» болгож **суурь зураг**-ийг
  (`heroReferenceUrl`) авч, сэдвээр дахин загварчилдаг. Солих горимд лавлах дүр зураг нь **тухайн баннерын
  одоогийн зураг** (хамгийн том хэмжээ / AI-ийн PNG мастер), prompt нь «бүх зүйлийг яг хэвээр үлдээ — хана,
  чулуу, чимэглэл, гэрэл, зохиомж; зөвхөн савнуудыг эдгээр бараагаар соль» (сэдвийн `mood`/`details` **орохгүй**).
  `buildHeroPrompt`-д `mode: "swap"`, generations route-д `mode` + `sceneUrl` (зөвхөн `hero/` storage зам —
  одоогийн `desktopRefUrl` шалгалттай ижил).
- **Шударга хязгаар:** загвар зургийг бүхэлд нь дахин зурдаг тул дэвсгэр **пиксел түвшинд** ижил гарахгүй —
  сүүдэр, чимэглэлийн жижиг зөрүү гарч болно. Тиймээс «Өмнө | Дараа» харьцуулалт, «Дахин оролдох» заавал байна.
  S4-ийн эхэнд нэг туршилт: зургийн баруун талд (үнэртний бүс) mask өгч засварлах нь илүү тогтвортой эсэхийг
  `gpt-image-2.6-sunburst` дээр шалгана (энэ загвар `input_fidelity`-г дэмжээгүй — plan §19; mask-ийг дэмжих
  эсэх нь **баталгаажаагүй**). Дэмжвэл mask-тай хувилбарыг хэрэглэнэ, UX өөрчлөгдөхгүй.
- Баннер дээрх бараа дэлгүүрт идэвхгүй (архивласан / нуусан) болвол баннерын жагсаалтад улбар тэмдэглэл:
  «Баннер дээрх Layton дэлгүүрт алга — үнэртнийг солих уу?». Автоматаар юу ч хийхгүй.

## 5. Алхмууд

### 5.1 ① Үндсэн

Гурван зүйл л асууна, төвлөрсөн нарийн багана (max ~560px), том талбарууд:

1. **Нэр** — «Жишээ: Black Friday, Цагаан сар». Доор нь: «Энэ нэр каталогийн шүүлтүүрт харагдана».
2. **Хэзээ** — эхлэх, дуусах өдөр (одоогийн `DatePicker`). Доор нь бүтэн өгүүлбэр:
   «11-р сарын 23-ны 00:00-оос 11-р сарын 30-ны 23:59 хүртэл — 8 хоног (Улаанбаатарын цагаар)».
3. **Холбоос** — саарал мөр `vonscent.mn/sale/black-friday` · [Хуулах] · [Өөрчлөх]. Тайлбар:
   «Сошиал пост, сторид энэ холбоосыг тавина. Баннерын товч автоматаар энд холбогдоно.»
   Нийтлэгдсэн арга хэмжээнд «Өөрчлөх» дээр анхааруулга: «Өмнө тараасан холбоос ажиллахаа болино».

Давхцал (өөр арга хэмжээтэй хугацаа + бараа) — ②-т, ⑤-д харуулна; энд биш.

### 5.2 ② Бараа, хямдрал

- Одоогийн `ItemsSection` (шүүлт, «бүгдийг сонгох», хэмжээ бүрийн хувь, «45,000 → 36,000» хүснэгт) —
  логик **хэвээр**, зөвхөн бүтэн өргөнд зөөнө: зүүн талд бараа сонгогч, баруун талд сонгосон бараа + хувь
  (≥lg хоёр багана, доош нь нэг).
- Дээр нь нэг мөр тойм: «12 бараа сонгосон · хямдрал 20–30%».
- Хувьгүй гишүүн («сонголт» арга хэмжээ) хэвээр зөвшөөрнө; тайлбар: «Хувь бичээгүй бараа үнээрээ үлдэж,
  зөвхөн энэ арга хэмжээний жагсаалтад орно».

- Жинхэнэ каталогийг iframe-ээр **ачаалахгүй** (live өгөгдөл шаардана). Оронд нь `CatalogPreview` —

- Тоолуурын текст: `formatCountdown(endsAt − startsAt)` — «эхлэх мөчид ингэж харагдана».

**Canvas-ийн дүрэм**

- Зураг сонгоогүй үед ч canvas харагдана: одоогийн үндсэн баннерын зураг (`home-content.ts`-ийн `HERO_PHOTO` — одоо export хийгдээгүй, export хийнэ) дээр **«Жишээ зураг»**
  шошготой. Админ AI зураг үүсэх 1–2 минутын хооронд текстээ засаж болно («Зураг бэлэн болтол текстээ засаарай»).
- **Компьютер** = 1440px, **Утас** = 390px iframe (одоогийн `/admin/hero-preview`, жинхэнэ `CampaignHero`).
  Canvas-ийн өргөнд багтаахаар scale (одоогийн `PreviewFrame`-ийн арга). Таблет 768-г эндээс хасаж ⑤-д
  «бүх хэмжээгээр» (унших) харуулна.
- Харагдац бүрт **тэнд гардаг** л зүйл засагдана:

  | Харагдац | Засагдах | Тэмдэглэл |
  |---|---|---|
  | Компьютер | дээд мөр, гарчиг, тайлбар (`description`), гол товч, нэмэлт товч | |
  | Утас | дээд мөр, гарчиг, тайлбар (`mobileDescription`), гол товч | Тайлбар хоосон бол компьютерынх бүдгээр харагдаж «Утсанд богино тайлбар бичих» гэнэ. Нэмэлт товч утсан дээр гарахгүй — canvas-ийн доор нэг мөр: «Нэмэлт товч зөвхөн компьютер дээр гарна» |

- Гарчиг компьютер дээр 2 мөрөөс хэтэрвэл (одоогийн `titleLines` хэмжилт) гарчгийн шошгон дээр улбар
  анхааруулга: «3 мөр болж байна — богиносговол цэвэрхэн». Хадгалахыг хориглохгүй.
- Хязгаар (`HERO_LIMITS`): дээд мөр 40, гарчиг 48, тайлбар 140, утасны тайлбар 70, товч 22. Хязгаарт хүрмэгц
  цааш бичигдэхгүй, тоологч улаан. Мөр таслах (Enter) байхгүй — Enter = дуусгах, Esc = буцаах.
- Товч дээр дарахад canvas-ийн **гадна**, доор нь жижиг цонх (popover): «Дарахад хаашаа очих вэ?» + D5-ийн
  жагсаалт; гол товчинд «Энэ арга хэмжээний бараанууд» сонгогдсон. Нэмэлт товчинд «Товчийг хасах».
- Preview доторх холбоосууд засварын горимд **ажиллахгүй** (дарахад засна, шилжихгүй).

**Зураг сонгох**

- **AI-аар үүсгэх** — одоогийн `HeroAiPanel`-ийн логик, шугаман болгож:
  1. Сэдэв — `HERO_THEMES`-ийн label-ууд chip-ээр (арга хэмжээний нэртэй таарвал урьдчилж сонгоно: «Black Friday» → `black_friday`).
  2. Баннерт гарах үнэртэн (ихдээ 3) — ②-т сонгосон бараанаас эхний 3-ыг **урьдчилж** бөглөнө; солих боломжтой.
  3. «Нэмэлт хүсэлт» (заавал биш, хураагдсан) + «Хурдан (чанар бага)» сонголт «Нэмэлт» дотор.
  4. **[Зураг үүсгэх]** → хувилбарууд сүлжээгээр гарна (үүсэж буй нь «≈1–2 минут» гэсэн skeleton-той).
     Хувилбар дээр дарахад canvas дээр **шууд** тавигдана (сонгосонд ✓). Томоор харах, устгах — одоогийнх.
  5. Компьютерын зураг сонгогдмогц «Утас» таб дээр: «Утасны зураг хэрэгтэй — **[Энэ зургаас утасны хувилбар
     үүсгэх]** эсвэл [Оруулах]». Автоматаар үүсгэхгүй (өдрийн хязгаар `HERO_AI_LIMITS.perDay`, зардал).
- **Өөрийн зураг оруулах** — одоогийн `ImageUpload` хоёр (компьютер, утас), шаардлагыг энгийнээр:
  «Компьютер: өргөн зураг (2.8:1), бараа баруун талд, зүүн тал хоосон хана. Утас: 4:3.»
- **Баннер хэрэггүй** — чагтлахад canvas хураагдана; холбоотой hero мөр байвал `is_active = false`
  болно (устгахгүй — буцааж асааж болно). ⑤-д «Нүүрний баннер солигдохгүй» гэж гарна.
- `hero_admin` туг хаалттай бол ④-р алхам stepper-т **гарахгүй** (4 алхам болно). AI түлхүүр
  тохируулаагүй бол (`isImageGenConfigured`) «AI-аар үүсгэх» карт идэвхгүй, шалтгаантай.

## 6. Inline засварын механизм

### 6.1 UX гэрээ (заавал)

1. Засагдах текст бүр hover/focus дээр хүрээ + нэрийн шошготой; гар (Tab) аар бүгдэд хүрнэ.
2. Дарахад **байгаа газраа** засагдана; бичих бүрт харагдац шууд шинэчлэгдэнэ.
3. Enter / гадна дарах = дуусгах. Esc = засахын өмнөх утга руу буцаах.
4. Хязгаараас хэтрэхгүй; тоологч харагдана. Paste хийхэд форматгүй текст, мөр таслалгүй.
5. Хоосон заавал биш талбар «+ … нэмэх» гэж бүдгээр үлдэнэ (алга болохгүй); заавал талбар (гарчиг, гол
   товчны бичиг) хоосон бол улаан хүрээ + ⑤-д жагсана.
6. `aria-label` = шошгоны нэр; screen reader-т талбар шиг уншигдана.

### 6.2 Бэлэн текст — `defaultHeroCopy(event)`

Баннер анх үүсэх мөчид нэг удаа бөглөнө (дараа нь админы бичсэнийг дарахгүй). Цэвэр функц, vitest-тэй:

| Талбар | Өгөгдмөл | Жишээ |
|---|---|---|
| Дээд мөр | `{нэр} · {эхлэх}–{дуусах}` (40-д багтахгүй бол зөвхөн огноо) | Black Friday · 11/23–11/30 |
| Гарчиг | `headline` байвал тэр, эс бөгөөс нэр (48-д тайрна) | Black Friday |
| Тайлбар | хувьтай бол «Сонгосон үнэртнүүд {max}% хүртэл хямдарлаа. {дуусах} хүртэл.»; хувьгүй бол «Энэ удаагийн онцгой сонголттой танилцаарай.» | |
| Утасны тайлбар | хувьтай бол «{max}% хүртэл хямдрал»; үгүй бол хоосон | 30% хүртэл хямдрал |
| Гол товч | хувьтай бол «Хямдралыг үзэх», үгүй бол «Сонголтыг үзэх» → энэ арга хэмжээ | |
| Нэмэлт товч | байхгүй | |

### 6.3 Техникийн арга

**Нэг нийтлэг компонент** — `EditableText` (`src/features/admin/components/editable-text.tsx`):
харагдах элементийн оронд ижил typography-тай (`font: inherit; color: inherit; background: transparent`)
`<textarea>` / `<input>`-ийг **ижил grid нүдэнд** үл үзэгдэх толин (mirror) span-тай давхарлаж тавина —
хэмжээ нь текстээ дагана, `field-sizing`-д найдахгүй. `maxLength`, controlled value, шошго, тоологч,
Enter/Esc. ③-р алхмын `CatalogPreview` үүнийг шууд хэрэглэнэ (админы хуудас дотор, iframe-гүй).

**Баннер (iframe доторх `CampaignHero`)** — дэлгүүрийн компонент LCP-д чухал тул засварын кодоор ачаалахгүй:

1. `HeroCopy`-ийн 4 текст, 2 товчинд зөвхөн **`data-hero-field="eyebrow|title|description|mobileDescription|primary|secondary"`**
   атрибут нэмнэ (дэлгүүрт зардалгүй, зан төлөв өөрчлөгдөхгүй).
2. `HeroPreviewFrame`-д `mode: "view" | "edit"` (postMessage-ээр). `edit` үед frame нь `[data-hero-field]`
   элементүүдийг олж: hover хүрээ + шошго зурна, дарахад тухайн элементийг
   `contenteditable="plaintext-only"` болгож focus өгнө, `beforeinput`-ээр хязгаар ба мөр таслалыг барина,
   `input` бүрт `{type: HERO_PREVIEW_EDIT, field, value}`-г эх цонх руу илгээнэ. Линкийн `click`-ийг `preventDefault`.
3. Эх цонх draft-аа шинэчилж campaign-ийг буцааж илгээнэ; frame **засагдаж буй талбарын** утгыг React-аар
   дахин бичихгүй (caret үсрэхгүй) — тухайн талбарыг focus-той байх хугацаанд «хөлдөөнө», blur дээр суллана.
4. Хоосон сонголтот талбар, «+ нэмэх» орлуулагчийг frame `edit` горимд өөрөө зурна (campaign-д `editPlaceholders` дамжуулна).
5. Товчны «хаашаа очих» цонх ба тоологчийг **эх цонхонд** зурна: frame элементийн `getBoundingClientRect()`-ийг
   `{field, rect}`-ээр илгээж, эх цонх scale-ээр үржүүлж байрлуулна.
6. Origin шалгалт, `e.source` шалгалт — одоогийнх шиг хэвээр.

**Нөөц хувилбар:** `contenteditable` scale-тэй iframe дотор тогтворгүй (caret, IME, Safari) гарвал 2–3-ыг
орхиж, дарсан элементийн rect дээр эх цонхноос `EditableText`-ийг давхарлана (элементийн computed
font/size/line-height/color-ийг frame-ээс авна). UX гэрээ (§6.1) **өөрчлөгдөхгүй**. Аль нь ч болсон
Chrome + Safari дээр гар туршилтаар баталгаажуулна.

   сольж товлоно — **нэг ч удаа** «энэ аль текст вэ», «холбоосыг яаж бичих вэ» гэж асуухгүй.
2. ⑤-р алхмыг уншаад «дуусахад юу болох»-ыг өөрийн үгээр хэлж чадна.
3. Арга хэмжээ ба баннерыг тусад нь холбох алхам байхгүй.
4. «Нүүрний баннер» хуудсыг хараад одоо аль баннер гарч байгаа, дараагийн улиралд юу гарахыг хэлж чадна.
5. Өвлийн баннерын нэг үнэртнийг өөр үнэртнээр сольж хадгална — зураг оруулах, сэдэв бичихгүйгээр.

Аль нэг нь бүтэхгүй бол тэр цэгийг засаж дахин туршина (§2-ын нотолгооны сул хэсгийг ингэж нөхнө).

## 12. Хамрахгүй

- Өгөгдлийн загвар, үнийн тооцоо, дэлгүүрийн харагдац, cron, кэш.
- Баннерын текстийн байрлал / фонт / өнгийг админ өөрчлөх (зохиомж кодод тогтмол — зөвхөн бараан/цагаан).
- Нэг арга хэмжээнд олон баннер, A/B.
- Улирлаас өөр давтагдах хуваарь (сар бүр, долоо хоног бүр); улирал бүрт олон баннер ээлжлэх.
- Баннер дээрх бараа дуусахад үнэртнийг **автоматаар** солих (зөвхөн тэмдэглэл гарна).
- AI-аар текст санал болгох (дараагийн санаа: «Гарчиг санал болгох» товч).
- «Бараагаар» хямдралын хуудас (`/admin/sales`).
