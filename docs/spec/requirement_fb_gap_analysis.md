1. 🔴 **Хүргэлтийн бүс админаас уншигдахгүй** — checkout нь код дотор бичсэн 2 бүсийг ашиглаж байна. Админ тохиргоо огт үйлчлэхгүй.

4. 🔴 **Хэмжээ тус бүрийн үлдэгдэл шалгагдахгүй** — 8ml үлдсэн байхад 20ml сонголт идэвхтэй хэвээр.
5. 🔴 **Админаас барааны зураг оруулах боломж байхгүй** — UI ч, API ч байхгүй.

## 1. Үнэ тооцох арга (Pricing)

### ❌ 1.1 Тогтмол зардал (сав баглаа + карго) нэмэгддэггүй
**Клиент:** «…үржээд дараа нь **сав баглаа карго хүргэлтийн зөрүү зардал /энэ нь тогтмол байдаг/** зэргийг нэмж боддог»

**Одоо:** `src/lib/pricing/calc.ts:62-64`
```ts
const basePerMl = bottlePrice / bottleMl;
const raw = basePerMl * tier.ml * tier.coefficient;   // ← тогтмол зардал нэмэгдээгүй
```
Мөн DB талд `supabase/migrations/0007_rpc.sql` доторх `recompute_variant_prices` мөн адил.

**Хэрэгтэй:** `settings.pricing`-д `fixedCost` (эсвэл хэмжээ тус бүрийн `fixedCost`) талбар нэмж, `raw = basePerMl * ml * coeff + fixedCost` болгох. TS болон SQL хоёуланг нь.

### ❌ 1.2 Барааны шинээр үүсгэх үед коэффициент тохиргооноос уншихгүй
**Клиент/requirement A2:** «Шатлалын коэффициент тохиргооноос уншина (A10)»

**Одоо:**
- `src/features/admin/components/price-calculator.tsx:37` → `DEFAULT_PRICE_TIERS` буюу **код дотор бичсэн** утгаас эхэлдэг (`src/lib/constants.ts:23`).
- `src/app/api/admin/products/route.ts:74` → мөн `DEFAULT_ROUND_TO` константыг ашиглаж `calcTierPrice` дуудна.
- Зөвхөн **засварлах** үед л (`recompute_variant_prices` RPC) `settings`-ээс уншина.

**Үр дагавар:** Админ A10 дээр коэффициентээ 1.8 → 1.4 болгож өөрчилсөн ч **шинээр нэмсэн бараа хуучин 1.8-аар** бодогдоно. Хуучин бараа засах үед л зөв болно — тогтворгүй үнэ.

### ⚠️ 1.3 Коэффициентийн анхны утга клиентийн хэлсэн мужаас гадуур
**Клиент:** «нэмэгдлийг /1,1-1,6 гэх мэт/»
**Одоо:** 5ml=1.8, 10ml=1.5, 20ml=1.3 (`src/lib/constants.ts:23-27`)

Тохиргооноос өөрчлөгддөг тул блокер биш, гэхдээ анхны утгыг 1.6 / 1.35 / 1.15 орчимд тааруулах нь зүйтэй.

### ✅ 1.4 Гар аргаар override хийх
`override_price` DB, `resolveVariantPrice()`, PriceCalculator-т бүгд ажиллана. Клиентийн «хэт өндөр үнэтэй ус дээр хувийг хасаж нэмдэг» гэсэн тохиолдлыг override-оор шийднэ. ✅

## 2. Зарах багцууд (ml хэмжээ)

### ⚠️ 2.1 2ml / 30ml өргөтгөх боломж хаалттай
**Клиент:** 2ml maybe soon, 30ml maybe soon, цаашид бүтэн сав (50/100ml, 60/90/125ml)

**Одоо:** `ML_SIZES = [5, 10, 20]` (`src/lib/constants.ts:15`) код дотор түгжигдсэн. PriceCalculator нь `DEFAULT_PRICE_TIERS`-ийн 3 мөрийг л зурна — **шинэ хэмжээ нэмэх UI байхгүй**. Админ Тохиргоо хуудас мөн зөвхөн байгаа 3 мөрийн коэффициентийг засна, мөр нэмэхгүй.

**Хэрэгтэй:** Тохиргоон дээр «шатлал нэмэх/устгах» товч, PriceCalculator-ыг settings-ээс динамикаар үүсгэх.

### ❌ 2.2 Бүтэн сав зарах загвар байхгүй
Бүтэн 50/100ml сав нь decant биш тул `inventory` (ml pool) загварт таарахгүй. Одоогийн бүтцээр бүтэн сав зарах боломжгүй. Ирээдүйн ажил гэж тэмдэглэв.

## 3. Үлдэгдэл ба хэмжээ тус бүрийн идэвх

### ❌ 3.1 Үлдэгдэл ml-ээс хамааран хэмжээ автоматаар идэвхгүй болохгүй ⛔ ЭРСДЭЛТЭЙ
**Клиент:** «сав нь дууссан тохиолдолд жишээлбэл **20мл ийг идэвхгүй болгох** боломжтой байна», «хэмжээ тус бүрийн тоо нь борлуулагдаж дуусах үед тухайн сонголт нь … дууссан идэвхгүй байдлаар харагдах»

**Одоо:**
- `src/features/products/api.ts:116` → `soldOut` нь **бүтээгдэхүүн бүхэлдээ** дууссан эсэх (available ≤ 0) л шалгана.
- `src/features/products/components/product-purchase.tsx:12` → `activeVariants` нь зөвхөн админы гараар тавьсан `is_active`-аар шүүнэ.
- Хаана ч `variant.ml > availableMl` шалгалт **байхгүй**.

**Үр дагавар:** Үлдэгдэл 8ml байхад хэрэглэгч 20ml-ийг сонгож, сагсанд хийж, checkout хүртэл явж байж «Уучлаарай, зарим бараа дууссан байна» гэсэн алдаа авна. Муу туршлага + захиалга алдагдана.

**Хэрэгтэй:** `mapProduct`-д `variant.available = availableMl >= v.ml` тооцоолж, ProductPurchase дээр disabled + «Дууссан» гэж харуулах. ProductCard дээр мөн.

### ⚠️ 3.2 Үүсгэсний дараа ml багцын идэвх/override засагдахгүй
`product-edit-form.tsx` дотор PriceCalculator **байхгүй** — зөвхөн `bottlePrice`/`bottleMl` засна. Тиймээс:
- 20ml-ийг гараар идэвхгүй болгох боломжгүй (зөвхөн бараа үүсгэх үед л),
- override үнэ засах боломжгүй.

Энэ нь клиентийн «сав дууссан үед 20мл-ийг идэвхгүй болгох» шаардлагыг бүрэн хаадаггүй.

### ✅ 3.3 Үлдэгдэл хэрэглэгчид харагдахгүй
`ProductDetail.availableMl` нь зөвхөн админ хуудсанд ашиглагдаж, storefront дээр тоо харагдахгүй. ✅

### ✅ 3.4 Нөөц нэмэхэд буцаж идэвхтэй болно
`restock_inventory()` / `release_inventory()` нь `is_sold_out`-ыг автоматаар цэвэрлэнэ. ✅

### ✅ 3.5 Гараар идэвхтэй/идэвхгүй болгох (үлдэгдлээс үл хамааран)
`products.is_active` + edit form дээрх checkbox ажиллана. ✅

## 4. Барааны мэдээлэл

### ❌ 4.1 Админаас зураг оруулах боломж байхгүй ⛔ ЭРСДЭЛТЭЙ
**Клиент:** олон зураг, шилтэй зураг, граммын савны зураг, танилцуулга слайд

**Одоо:**
- `product-form.tsx` — зураг оруулах талбар **огт байхгүй**
- `product-edit-form.tsx` — мөн байхгүй
- `POST /api/admin/products` — `product_images` хүснэгтэд **юу ч оруулдаггүй**

`/api/admin/upload` route нь байгаа (баннер/аватарт ашиглагддаг) тул суурь нь бэлэн, гэхдээ бараанд холбогдоогүй.

### ❌ 4.2 Дэлгэрэнгүй тайлбар 4 хэсэгт хуваагдаагүй
**Клиент:** (1) ерөнхий ус/брэндийн танилцуулга, (2) нотуудын тайлбар, (3) хаана хэзээ хэрэглэх, (4) товч тайлбар — **4 хэсэгтэй**

**Одоо:** `products.description` ганц text талбар, админд ганц `<textarea rows={3}>`.

**Хэрэгтэй:** DB-д 4 багана (эсвэл `description jsonb`), админд 4 талбар, детэйл хуудсанд 4 хэсгээр зурах.

### ⚠️ 4.3 Зургийн галерей автоматаар эргэхгүй
**Клиент:** «3н зурагтай өөрөө автоматаар 3-5 сек эргэдэг **эсвэл** гараар эргүүлж болдог байх»

**Одоо:** `product-gallery.tsx` — гар свайп ✅, thumbnail ✅, **автомат эргэлт байхгүй**. Клиент «эсвэл» гэсэн тул техникийн хувьд хангасан ч зорилго нь автомат эргэлт байсан.

### ⚠️ 4.4 Төстэй бараа таг-аар таарахгүй
**Клиент:** «Энэ уснууд нь аль болох **олон таг нь таарсан** уснууд байх»

**Одоо:** `getRelated()` (`api.ts:267`) — зөвхөн `scentFamily === ...` **эсвэл** `brand === ...`. Оноо (score) тооцох логик байхгүй, эрэмбэлэхгүй, эхний 4-ийг л авна.

**Хэрэгтэй:** gender / family / season / concentration / tags давхцлыг оноогоор жинлэн эрэмбэлэх.

### ✅ 4.5 Бусад баганууд
Нот (top/heart/base) ✅, хүйс ✅, төрөл (EDP/EDT/Parfum/EDC/**Extrait**/**Elixir** — `0016_types_loyalty.sql`) ✅, гарал үүсэл ✅, гаргасан он ✅, улирлын таг ✅ (`0017_season.sql`), таг (шинэ/эрэлттэй/хямдрал) ✅.

### ✅ 4.6 ml үнэ preview
Хамгийн бага ml-ийн үнэ default (`startingPrice = Math.min(...)`) ✅, хэмжээ дарахад үнэ солигдоно ✅, **мөн** хэмжээ тус бүрийн доор үнэ харагдана ✅ (клиентийн «алин ч болно»-г хоёуланг нь хийсэн).

## 10. Купон (Coupons)

### ❌ 10.1 Хувь хүнд зориулсан купон байхгүй
**Клиент:** «Дараах нь **зөвхөн тэр хүнд зориулсан** купон. 300,000-с дээш захиалгад дараагийн захиалгадаа ашиглах 10 хувь хөнгөлөх купон … тухайн үнийн дүнгийн худалдан авалт хийсэн тохиолдолд **рандом код тухайн хүний купон хэсэгт автоматаар орно**»

**Одоо:** `coupons` хүснэгтэд `user_id` **байхгүй**. Автоматаар код үүсгэх логик байхгүй. Бүх купон нь глобал.

**Хэрэгтэй:**
- `coupons.user_id uuid null` (null = глобал) + RLS
- `coupon_redemptions(coupon_id, user_id)` — хүн тус бүрийн ашиглалтын тоо
- `mark_order_paid()` дотор `subtotal ≥ 300000` бол рандом код үүсгэж, хугацаатай олгох

### ❌ 10.2 Нэг хүний ашиглах тооны хязгаар байхгүй
**Клиент:** «хэдэн хүнч бай **эсвэл нэг хүн хэдэн удаач** ашиглаж болно»
**Одоо:** `coupons.max_uses` нь зөвхөн **нийт** ашиглалт. `used_count` глобал тоолуур. Нэг хэрэглэгч 10 удаа дараалан ашиглаж болно.
