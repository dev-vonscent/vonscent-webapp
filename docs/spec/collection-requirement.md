# Collection (Багц) — Бүрэн шаардлага

> **Эх сурвалж:** Клиентийн товч тайлбар (VONSCENT Collection logic) + §14-т өгсөн
> албан ёсны хариултууд.
> Энэ баримт нь тухайн шаардлагыг одоогийн кодын суурь
> (`products`/`product_variants`, `settings`, `coupons`, `place_order` RPC,
> zustand cart store) дээр буулгаж, хэрэгжүүлэхэд бэлэн болгосон дэлгэрэнгүй хувилбар.

**Тэмдэглэгээ:** `[ ]` хийгээгүй · `[x]` хийгдсэн · 🔵 DB migration шаардана · 🟢 DB өөрчлөлт шаардахгүй

> **Шийдвэрлэгдсэн (клиентээс, §14):** купон **давхар** бодогдоно · custom багцыг
> нэр өгч **хадгалах** (профайл → «Миний багцууд») · base = **тогтмол 4** ·
> custom дээд хязгаар **default хязгааргүй** (`maxItems` тохируулж болно) · багц бүр
> **нэг ижил ml**-тэй, detail хуудас дээр ml сонгоход үнэ **live-аар** өөрчлөгдөнө ·
> зөвхөн **5/10/20ml** · хямдрал зөвхөн **%** · багц бүрд **нэмэлт бэлэг** дагалдана.

---

## 1. Тодорхойлолт ба нэр томьёо

**Collection = Багц.** Хэд хэдэн үнэртэнг (decant) нэг багц болгон нэгтгэж,
нийт үнээс тодорхой хувиар хямдруулан зардаг бүтээгдэхүүн. Багц бүр **нэмэлт бэлэгтэй** (§3.3).

Багц **2 өөр ойлглолттой**:

| Нэр | Монгол нэр | Хэн угсрах | Төрлүүдийн тоо | Хямдрал |
|---|---|---|---|---|
| **Base collection** | Бэлэн багц | Админ | Яг **4** өөр үнэртэн | Багц бүрт тохируулна (default **5%**) |
| **Custom collection** | Өөрийн багц | Хэрэглэгч | Хамгийн багадаа **4**, дээд тал нь хязгааргүй¹ | Админаас тохируулна (default **5%**) |

¹ Дээд хязгаарыг админ тохиргооноос (`maxItems`) хязгаарлаж болно; default нь хязгааргүй.

**Төрөл** гэдэг нь багц доторх тодорхой **үнэртэн (`product`)**-г хэлнэ. **ml хэмжээ нь
төрөл бүрд биш, багц түвшинд нэг удаа** сонгогдоно (§2.2). Нэг багц дотор нэг
бараа **давхардахгүй** (4 *өөр* үнэртэн гэсэн шаардлагад нийцүүлэв).

## 2. Бизнесийн үндсэн дүрэм

1. **Хямдрал нь багцын төрлүүдийн нийлбэр үнэн дээр** тооцогдоно
   (`Σ төрлийн variant үнэ`). Төрөл бүр сонгогдсон ml-ийн идэвхтэй үнээр орно
   (override_price → auto_price, `variant_price()`-тэй ижил дүрэм).
2. **ml нэгдмэл:** багц бүр **нэг ижил ml (5/10/20)**-тэй. Detail хуудсан дээр ml
   сонгоход бүх төрөлд мөрдөгдөж, үнэ **live-аар** дахин бодогдоно (одоогийн барааны
   дэлгэрэнгүй хуудасны ml сонголттой ижил зан төлөв). Багцад **sample (1–2ml)
   төрөл байхгүй** — зөвхөн 5/10/20ml decant.
3. **Хямдралын хувь** нь багц/тохиргооноос уншигдана (зөвхөн **%**). Тухайлан
   заагаагүй бол default **5%**. Тогтсон дүнгийн (₮) хямдрал байхгүй.
4. **Тоймлолт** нь `settings.pricing.roundTo`-г ашиглана (одоо 100₮).
   Багцын үнэ = `roundTo(Σ төрөл(ml) × (1 − discountPct/100))`.
5. Багцын хямдрал нь **бүтээгдэхүүний хямдрал** гэж тооцогдоно —
   хүргэлтийн төлбөр **үргэлж хамгийн сүүлд** нэмэгдэнэ (одоо мөрдөж буй дүрэм).
6. **Купон давхар бодогдоно:** багцын хямдралын **дараах** дэд дүн дээр купон нэмж
   бодогдоно (нэг л купон, зөвхөн бүтээгдэхүүнээс — одоогийн дүрэм хэвээр).
7. **V point (loyalty)** нь бүх хямдралын (багц + купон) **дараах** дүнгээс,
   хүргэлтийг оролцуулахгүйгээр хуримтлагдана (одоо мөрдөж буй дүрэмтэй ижил).
8. **Нэмэлт бэлэг** нь үнэ төлбөргүй (unit_price 0), багцын дэд дүнд нэмэгдэхгүй
   боловч түүний ml нь бэлэг барааны үлдэгдлээс хасагдана (§3.3, §6.1).
9. Багцын **бүх төрөл идэвхтэй** ба сонгосон ml-д **үлдэгдэлтэй** байх ёстой. Аль
   нэг төрөл идэвхгүй/дууссан бол багцыг «Түр байхгүй» болгож, сагсанд нэмэхийг хориглоно.
10. **Free shipping** босго (`settings.shipping.freeOver`) нь хямдралын дараах
    дэд дүнгээр шалгагдана (одоогийн `resolveShipping` дүрэмтэй нийцнэ).

## 3. Base collection (Бэлэн багц) — дэлгэрэнгүй

### 3.1 Бүтэц
- Яг **4 өөр үнэртэн (бараа)**-аас бүрдэнэ (тогтмол 4). Төрөл = `product`.
- Багцын мэдээлэл (баганууд):
  - **Нэр** (`name`)
  - **Slug** (`slug`, URL-д)
  - **Хүйс** (`gender` — male/female/unisex, шүүлтэд)
  - **Тайлбар** (`description`)
  - **Хямдралын хувь** (`discount_pct`, default 5)
  - **Зураг** (`image_url`) — багцын танилцуулга зураг
  - **4 төрөл** (`collection_items` — бараа + эрэмбэ)
  - **Бэлгийн ml** (`gift_ml`, сонголттой — тохиргооны default-ыг дарж болно, §3.3)
  - **Идэвхтэй эсэх** (`is_active` — нийтлэх/нуух)
  - **Онцлох** (`is_featured`, сонголттой — нүүр хуудсанд гаргах)

### 3.2 ml сонголт ба үнэ бодогдох
Detail хуудас нь **барааны дэлгэрэнгүй хуудастай төстэй**: 5/10/20 товч, ml
сонгоход үнэ шинэчлэгдэнэ.
```
memberSum(ml) = Σ variant_price(төрөл.product, ml)      // сонгосон ml дэх идэвхтэй үнэ
price(ml)     = roundTo( memberSum(ml) × (1 − discount_pct/100) )
saved(ml)     = memberSum(ml) − price(ml)                 // «X₮ хэмнэнэ» badge
```
- **Боломжит ml** = бүх 4 төрөл идэвхтэй variant + үлдэгдэлтэй байгаа ml-үүдийн
  огтлолцол. Аль нэг төрөл тухайн ml-д дутуу бол тэр ml сонголт идэвхгүй.
- Төрлийн үнэ өөрчлөгдвөл багцын үнэ **live-аар** дагаж өөрчлөгдөнө (тогтсон үнэ хадгалахгүй).

### 3.3 Нэмэлт бэлэг (Gift) 🎁
- **Багц бүр нэмэлт бэлэгтэй.** Худалдан авагч багцад **ороогүй** нэг үнэртнийг
  бэлгээр сонгож, **админаас тохируулсан хэмжээгээр** (ихэвчлэн **1ml эсвэл 2ml**)
  үнэ төлбөргүй авна.
- Бэлгийн ml нь `collections.gift_ml` (per-collection override) → байхгүй бол
  `settings.collection.giftMl` (глобал default).
- **Дүрэм:**
  - Бэлэг бараа нь тухайн багцын 4 төрлийн аль нэг **байж болохгүй**.
  - Бэлэг нь дэд дүнд нэмэгдэхгүй (үнэ 0), гэхдээ бэлгийн ml нь бэлэг барааны
    үлдэгдлээс **хасагдана** (reserve/commit — §6.1).
  - Бэлэг бараа сонгосон ml-д (1–2ml) үлдэгдэлгүй бол сонгуулахгүй/сануулна.
- Глобал идэвх: `settings.collection.giftEnabled` (default `true`).

### 3.4 Админ CRUD
- `/admin/collections` дээрээс **үүсгэх / засах / устгах / идэвх солих**.
- Төрөл сонгох UI: бараа хайх → 4 бараа бүрдтэл нэмэх (ml сонгохгүй), эрэмбэ.
- Бэлгийн ml тохируулах (эсвэл глобал default ашиглах).
- Preview: ml тус бүрээр `memberSum`, `price`, `saved`-ыг **амьд** харуулна.

## 4. Custom collection (Өөрийн багц) — дэлгэрэнгүй

### 4.1 Бүтэц
- Хэрэглэгч өөрөө **≥ 4 үнэртэн** сонгож угсарна (дээд тал `maxItems`, default ∞).
- Төрөл бүр = `product` (давхардахгүй бараа). ml нь багц түвшинд нэг (§2.2).
- Хямдралын хувь нь **админ тохиргооноос** (`settings.collection.customDiscountPct`, default 5).
- Custom багц ч мөн **нэмэлт бэлэгтэй** (§3.3): худалдан авагч угсарсан багцдаа
  ороогүй нэг үнэртнийг бэлгээр сонгож, үнэ төлбөргүй авна. Бэлгийн ml нь
  `settings.collection.giftMl` (глобал default) — custom-д per-collection
  `gift_ml` override байхгүй. Бэлэг сонголт нь угсрагч дээр гардаг (§7 build).

### 4.2 ml сонголт ба үнэ бодогдох
```
memberSum(ml) = Σ variant_price(төрөл.product, ml)
price(ml)     = roundTo( memberSum(ml) × (1 − customDiscountPct/100) )
```
- Эхлээд **ml сонгоно** → тухайн ml-д идэвхтэй, үлдэгдэлтэй бараанууд л сонгогдоно.
- Төрөл нэмэх/хасах бүрт үнэ, хямдрал, хэмнэлт **live-аар** шинэчлэгдэнэ.
- Төрлийн тоо `minItems`-ээс бага бол «Багцлах» товч идэвхгүй,
  «дор хаяж 4 үнэртэн нэмнэ үү» гэсэн сануулга.

### 4.3 Хадгалах (Миний багцууд)
- Нэвтэрсэн хэрэглэгч угсарсан багцдаа **нэр өгч хадгална**.
- Хадгалсан багц нь **профайл хуудасны «Миний багцууд»** хэсэгт харагдана
  (`/account/collections`) — харах, сагсанд нэмэх, нэр солих, устгах.
- Хадгалсан custom багц нь `collections` (`type='custom'`, `user_id` = эзэн) +
  `collection_items` мөрөөр DB-д хадгалагдана (§5.1). ml нь хадгалагдахгүй —
  сагсанд нэмэх үед дахин сонгогдоно.
- Зочин (нэвтрээгүй) хэрэглэгч custom багц угсарч **сагсанд нэмж** болно, харин
  хадгалахын тулд нэвтрэх шаардлагатай (сануулга гарна).

### 4.4 Админ тохиргоо (`settings.collection`)
| Түлхүүр | Утга | Default |
|---|---|---|
| `customEnabled` | Custom багц идэвхтэй эсэх | `true` |
| `minItems` | Доод төрлийн тоо | `4` |
| `maxItems` | Дээд төрлийн тоо (`null` = хязгааргүй) | `null` |
| `customDiscountPct` | Custom-ийн хямдрал % | `5` |
| `baseDefaultDiscountPct` | Шинэ base багцын анхны хямдрал % | `5` |
| `giftEnabled` | Нэмэлт бэлэг идэвхтэй эсэх | `true` |
| `giftMl` | Бэлгийн default ml | `1` |
| `giftMlOptions` | Админд сонгуулах бэлгийн ml-үүд | `[1, 2]` |

## 5. Дата модель (🔵 migration `0028_collections.sql`)

### 5.1 Шинэ хүснэгтүүд
```sql
create type collection_type_t as enum ('base', 'custom');

create table collections (
  id            uuid primary key default gen_random_uuid(),
  slug          text unique not null,
  type          collection_type_t not null default 'base',
  user_id       uuid references profiles(id) on delete cascade,  -- null=base(admin), set=хадгалсан custom
  name          text not null,
  gender        gender_t not null default 'unisex',              -- багцын хүйс (шүүлтэд)
  description   text default '',
  discount_pct  numeric(5,2) not null default 5 check (discount_pct between 0 and 100),
  image_url     text,
  gift_ml       int check (gift_ml is null or gift_ml > 0),       -- null → settings default
  is_active     boolean not null default true,
  is_featured   boolean not null default false,
  created_at    timestamptz not null default now(),
  updated_at    timestamptz not null default now()
);

create table collection_items (
  collection_id uuid not null references collections(id) on delete cascade,
  product_id    uuid not null references products(id) on delete restrict,
  sort_order    int not null default 0,
  primary key (collection_id, product_id)   -- нэг барааг давхардуулахгүй
);
```
- `collection_items`-д **variant_id/ml байхгүй** — төрөл зөвхөн бараа; ml нь
  сагсанд нэмэх үед сонгогдож, `(product_id, selected_ml)`-аар variant руу шийдэгдэнэ.
- `settings` хүснэгтэд `('collection', {...})` мөр нэмнэ (§4.4).
- **RLS:** base (`user_id is null`, `is_active`) нийтэд унших; хадгалсан custom
  (`user_id`) зөвхөн эзэн нь унших/засах; бүх бичилт админ эсвэл эзэн.

### 5.2 Захиалгад холбох (order_items өргөтгөл)
Багц захиалагдахад түүний төрлүүд болон бэлэг нь **тус тусдаа order_item** болж
бичигдэнэ (inventory reserve нь ml тус бүрээр ажилладаг — §6.1). Багцыг хэвлэх/
харуулахад бүлэг болгон харуулахын тулд:
```sql
alter table order_items
  add column collection_id   uuid references collections(id) on delete set null,
  add column collection_name text,
  add column is_gift         boolean not null default false;
```
- Багцын **төрлүүд** нь сонгосон **нэг ижил ml**-ээр орно; багцын хямдралыг төрөл
  мөрүүд рүү **пропорциональ** тарааж `unit_price`/`line_total` дээр буулгана
  (нийлбэр нь багцын үнэтэй тэнцэнэ; тоймлолтын үлдэгдлийг сүүлийн мөрөнд залруулна).
- Багцын **бэлэг** нь тусдаа мөр: `is_gift=true`, `unit_price=0`, `ml=gift_ml`,
  `qty = багцын qty`, `collection_id` тавьсан.

> **Альтернатив (энгийн):** төрлүүдийг бүтэн үнээр бичээд, багцын нийт хямдралыг
> `orders.discount` дээр нэмэх. Гэхдээ энэ нь купоны discount-той нэг талбарт
> холилдох тул мөр тус бүрийн traceability алдагдана. **Санал: пропорциональ арга.**

## 6. Үнэ, хямдрал, checkout урсгал

### 6.1 Inventory / reserve
- Багц = N ширхэг decant мөр + 1 бэлэг мөр. `place_order` RPC-д `p_items` дотор
  төрөл бүр **тусдаа мөр** (`product_id, variant_id, ml, qty`), бэлэг мөр
  (`product_id, variant_id=null, ml=gift_ml, qty, is_gift=true`) болж орно —
  reserve/commit/release логик өөрчлөлтгүй ажиллана.
- Багцын тоо ширхэг (`qty`) N бол төрөл бүрийн `ml × N`, бэлгийн `gift_ml × N` reserve хийгдэнэ.
- Аль нэг төрөл эсвэл бэлэг дутвал бүх багц reserve амжилтгүй → захиалга rollback.

### 6.2 Сагсны бүтэц (zustand `cart/store.ts` өргөтгөл)
Одоогийн `CartItem` нь `variantId`-аар түлхүүрлэгддэг. Багцыг дэмжихийн тулд:
- Мөрийн төрөл нэмэх: `kind: 'product' | 'collection'`.
- Collection мөр:
  ```ts
  interface CartCollection {
    key: string;                 // collectionId эсвэл custom hash
    kind: 'collection';
    collectionId: string | null; // base/хадгалсан бол id, ephemeral custom бол null
    type: 'base' | 'custom';
    name: string;
    image: string | null;
    discountPct: number;
    ml: number;                  // багц даяар нэг сонгосон ml
    members: { productId; variantId; name; brand; unitPrice }[];  // тухайн ml дэх
    gift: { productId; name; ml } | null;  // сонгосон бэлэг
    unitPrice: number;           // хямдарсан багцын үнэ (бэлэггүй)
    qty: number;
  }
  ```
- `selectSubtotal` нь collection мөрийн `unitPrice × qty`-г нэмнэ (бэлэг 0).
- Багцыг сагснаас **бүлгээр** засах/устгах; ml солиход төрөл үнэ/боломж дахин шалгагдана.
- Checkout үед collection мөр нь төрөл + бэлэг order_item болж **задарна** (§5.2).

### 6.3 Хямдралын дараалал
```
subtotal(бараа + багцны хямдарсан үнэ; бэлэг 0)
  → купон (нэг л купон, бүтээгдэхүүнээс — багц хямдралын ДАРАА, давхар)
  → V point ашиглалт
  → хүргэлт (хамгийн сүүлд)
```
- V point нь дээрх бүх хямдралын дараах дүнгээс, хүргэлтгүйгээр хуримтлагдана.

## 7. Storefront (хэрэглэгчийн тал)

- [ ] **`/collections`** — бэлэн багцуудын жагсаалт (card: зураг, нэр, эхлэх үнэ,
      хямдрал badge, «X₮ хэмнэнэ»). 🔵
- [ ] **`/collections/[slug]`** — багцын дэлгэрэнгүй, **барааны дэлгэрэнгүйтэй төстэй**:
      - 4 төрөл (бараа бүрийн зураг/нэр/линк).
      - **ml сонголт (5/10/20)** → үнэ/хэмнэлт **live-аар** шинэчлэгдэнэ.
      - **🎁 Бэлэг сонгогч** — багцад ороогүй үнэртнээс нэгийг сонгох (админ ml).
      - Нийт үнэ, хямдарсан үнэ, «Сагсанд нэмэх». 🔵
- [ ] **`/collections/build`** — **Custom багц угсрагч**:

## 11. Edge case / анхаарах зүйлс

- **Төрөл идэвхгүй/устсан:** base багц автоматаар «Түр байхгүй»; админд сануулга.
- **ml боломж:** боломжит ml = бүх төрөл идэвхтэй+үлдэгдэлтэй ml-үүдийн огтлолцол;
  хоосон бол багц «Түр байхгүй».
- **Бэлэг:** төрөлтэй давхцаж болохгүй; сонгосон `gift_ml`-д үлдэгдэлгүй бол блоклоно;
  `giftEnabled=false` үед бэлгийн алхам гарахгүй.
- **Үнэ өөрчлөгдсөн:** base/custom үнэ амьд дагана; сагсанд байгаа багцыг checkout-д
  дахин баталгаажуулж, өөрчлөгдсөн бол хэрэглэгчид мэдэгдэнэ.
- **Тоймлолт:** багцын үнэ болон төрөлд тараах discount дээр rounding
  үлдэгдлийг сүүлийн мөрөнд залруулна.
- **Хадгалсан custom:** дараа нь төрөл бараа уствал тухайн багцад «энэ бараа
  байхгүй болсон» тэмдэглэж, сагсанд нэмэхээс өмнө засуулна.
- **Reorder:** багц захиалгыг дахин захиалахад төрөл + бэлэг одоогийн үнэ/үлдэгдлээр шалгагдана.
- **Free shipping / V point:** багц хямдралын дараах дүнгээр бодогдоно (§2.10, §2.7).
- **Купон + багц:** давхар зөвшөөрөгдсөн (§6.3) — багц хямдралын дараах дэд дүнгээс.

   - **`[ Багц үүсгэх ]`** — гишүүн `< minItems` (4) үед **disabled**; `≥ minItems`
     болмогц идэвхжинэ (клиентийн «4 сонгоход идэвхтэй болно»). `maxItems`-д хүрвэл
     grid-ийн `[ + ]` disabled + «дээд хязгаарт хүрсэн» hint.
   - Mobile дээр tray нь collapsed pill → дарахад bottom sheet болж дэлгэрнэ.
4. **«Багц үүсгэх» дарахад — нэр/тайлбарын форм** (Dialog/Sheet):
   ```
   ┌─── Багц үүсгэх ───┐
   │ Нэр*     [_______]│
   │ Тайлбар  [_______]│
   │ ☐ Хадгалах (Миний багцууд)   ← нэвтэрсэн үед
   │ [Болих] [Сагсанд нэмэх]      │
   └───────────────────┘
   ```
   - **Нэвтэрсэн:** «☐ Хадгалах» сонговол `/account/collections`-д хадгална, дараа
     нь сагсанд нэмнэ. Тэмдэглээгүй бол зөвхөн сагсанд.
   - **Зочин:** нэр заавал биш; «Хадгалах»-ын оронд «Хадгалахын тулд нэвтэрнэ үү»
     hint + шууд «Сагсанд нэмэх».
   - Амжилттай → toast «Багц сагсанд нэмэгдлээ» + CartSheet онгойлгох сонголт.

**Empty/edge:** сонгоогүй үед tray «Дуртай үнэртнээ нэмж эхэлнэ үү» placeholder;
ml өөрчлөхөд тохирохгүй болсон сонголтыг сэрэмжлүүлж авто-хасна.

### 15.6 Сагс дахь багц (cart rendering) 🟢

Багц мөрийг **бүлэг карт** болгон харуулна (ганц бараанаас ялгаатай):
```
┌─ Багц: «Өвлийн дулаан 4»  (10ml)  −5% 🎁 ─┐
│  ▸ Brand — Нэр                             │
│  ▸ … ×4                                     │
│  🎁 Бэлэг: Brand — Нэр (1ml)  ·  0₮         │
│  Тоо: [− 1 +]              128,250₮   [🗑]  │
└────────────────────────────────────────────┘
```
- Гишүүд + бэлэг задарч харагдана; үнэ = багц үнэ. Засах/устгах **бүлгээр**.
- ml солих: mini-select (боломжит ml), үнэ дахин бодогдоно.
- base багц дээр «дэлгэрэнгүй» линк; custom дээр «засах» → builder руу prefill.

### 15.7 Миний багцууд (`/account/collections`) 🔵

- Хадгалсан custom багцын карт жагсаалт (нэр, гишүүд preview, огноо).
- Үйлдэл: **Сагсанд нэмэх** (ml сонгуулна), **Нэр солих**, **Устгах** (`ConfirmDialog`).
- Хоосон төлөв: «Хадгалсан багц алга — эхнийхээ угсараарай» + CTA → build.
- Профайл цэс (`profile-menu` / account layout)-д «Миний багцууд» мөр нэмэх.

### 15.8 Ерөнхий зарчим (responsive · a11y · motion · i18n)

- **Дахин ашиглалт:** `CatalogFilters/Sort/Search`, `ProductGrid/ProductCard`,
  `quick-add`, `SectionHeading`, `CartSheet`, `Dialog/Sheet`, `Button`, `Badge`,
  `ConfirmDialog` — шинээр бүтээхээс илүү тохируулж ашиглана.
- **Responsive:** desktop = sidebar + grid (каталог шиг); mobile = дээд controls
  мөр + selection tray нь bottom sheet. `bottom-nav`-тай давхцахгүйгээр tray-д
  `pb-safe` + доод зай.
- **A11y:** `[ + ]`/`[ ✓ ]` товчид `aria-pressed`; ml segment `role="radiogroup"`;
  tray-д сонгосон тоог `aria-live`; combobox бэлэг сонголт keyboard-аар.
- **Motion:** карт hover subtle rise, нэмэх үед bottle тray руу «нислэг» (жижиг,
  `prefers-reduced-motion`-д унтраана), badge count spring.
- **i18n:** бүх шошго монголоор (Багц, Бэлэн багц, Өөрийн багц, Багц угсрах, Бэлэг,
  Хэмнэнэ, Багц үүсгэх, Миний багцууд). Мөнгө `formatMNT`, тоо `roundTo`.
- **Гүйцэтгэл:** `/collections` ISR (каталог шиг `revalidate`); builder client-side
  сонголт, үнэ сервер `/api/collections/price`-аар баталгаажна (§9).
