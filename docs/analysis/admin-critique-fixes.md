## Алхам 4 — [P1] Хамгийн чухал хоёр форм screen reader-т нэргүй байсан

### 4.1 Хуулбарласан `Field` нь зөвийг нь дарж байсан

**Буруу байсан нь.** `product-form.tsx` болон `product-edit-form.tsx` тус бүр
дотроо **өөрийн `Field` компонент** тодорхойлсон байв:

```tsx
function Field({ label, children }) {
  return (<div className="space-y-1.5"><Label>{label}</Label>{children}</div>);
}
```

`htmlFor` алга, хүүхэд элементэд `id` алга — өөрөөр хэлбэл **label ба input
хоорондоо огт холбогдоогүй**. Үр дүнд нь бараа үүсгэх / засах хоёр формын
**~25 инпут screen reader дээр «edit text, blank» гэж уншигдана**. Sam
(харааны бэрхшээлтэй хэрэглэгч) эдгээр формыг бөглөх бүрэн боломжгүй байв.

Хамгийн эвгүй нь: `src/components/ui/field.tsx`-д **зөв хувилбар нь аль хэдийн
байсан** — `useId()`-аар id үүсгэж, `htmlFor` холбож, `aria-describedby` /
`aria-invalid`-ыг контекстээр дамжуулж, `role="alert"`-тай `FieldError`
гаргадаг. `customer-control.tsx` түүнийг импортолдог; энэ хоёр форм л дарж
бичсэн байв.

**Болгосон нь.** Хоёр локал `Field`-ийг **устгаж**, `@/components/ui/field`-ээс
импортлов. Код нэмээгүй — хассан. `product-form.tsx`-ийн ашиглагдахаа больсон
`Label` импортыг мөн цэвэрлэв.

### 4.2 «Алдаа гарлаа.» → серверийн жинхэнэ шалтгаан

**Буруу байсан нь.** 30 талбар бөглөсний дараа гарах цорын ганц мессеж нь
`"Алдаа гарлаа."` — ямар талбар, яагаад гэдэг нь алга. Мөн `await res.json()`
нь `try/catch`-гүй тул сервер JSON биш хариу буцаавал бүр цаана нь шидэгдэнэ.

**Болгосон нь.** `res.json().catch(() => null)`, дараа нь:
- серверийн `error` байвал → `Хадгалж чадсангүй: <шалтгаан>`
- байхгүй бол → `Хадгалж чадсангүй. Сервер хариу өгсөнгүй (500). Дахин оролдоно уу.`
- сүлжээ тасарвал → `Сүлжээнд холбогдож чадсангүй. Дахин оролдоно уу.`

Устгах үйлдэл (`product-edit-form.remove`) мөн адил — өмнө нь `if (res.ok)`
байсан тул амжилтгүй устгалт **чимээгүй өнгөрдөг** байсан.

## Алхам 10 — [P1] Эцсийн төлөв захиалгыг гацаадаг байв

**Буруу байсан нь.** Алхам 2-ийн state machine нь `delivered: []`, `cancelled: []`
гэж **бүрэн эцсийн** болгосон. Андуурч цуцалсан захиалгыг UI-аас сэргээх арга
алга — өөрөөр хэлбэл сэргээх зардлыг Select-ээс **Supabase консол руу, аудитын
мөрөөс гадагш** зөөсөн. Мөн «хүргэлт бүтэлгүйтэж буцсан» (`shipping →
confirmed`) гэсэн Улаанбаатарын өдөр тутмын нөхцөл боломжгүй байв.

**Болгосон нь.**
- `shipping → confirmed` нэмэв (жирийн шилжилт, бүх оператор).
- `RECOVERY_STATUSES`: `delivered → shipping`, `cancelled → pending` —
  **зөвхөн super_admin**. `getStaffUser()`-ээр эрхийг шалгаж
  `canRecover` prop-оор дамжуулна.
- Шилжилт бүрд өөрийн тайлбартай confirm (`GUARDED` зураглал): сэргээх нь
  `destructive` биш, цуцлах нь мөн хэвээр.
- Эцсийн төлөвийн мессежид гарц нэмэв: «Андуурсан бол супер админаар
  сэргээлгэнэ үү».

**Сервер тал (энэ нь илүү чухал).** `POST /api/admin/orders/[id]/status` нь
**ямар ч шилжилтийг зөвшөөрдөг** байсан бөгөөд `callRpc`-ийн үр дүнг үл
тоомсорлож `{ok:true}` буцаадаг байв — өөрөөр хэлбэл client талын бүх засвар
дээр сервер өөрөө худал хэлж байсан. Одоо:
- Одоогийн төлөвийг DB-ээс уншиж, ижил зураглалаар шалгана
  (CLAUDE.md: «эрх шалгалтыг route handler бүр дотор давт»);
  зөрчвөл `409 ILLEGAL_TRANSITION`.
- Сэргээх шилжилт зөвхөн `staff.role === "super_admin"`.
- `mark_order_paid`, `update_order_status`, `mark_order_refunded` гурвуулангийн
  алдааг барьж `500` + шалтгаан буцаана.

## Алхам 11 — [P1] Карт горим эрэмбийг алдуулж, DOM-ыг хоёр дахин ачаалдаг байв

**Буруу байсан нь.** Алхам 6.1-д хүснэгтийг `hidden md:block`-оор нуусан.
CSS-ээр нуухад React **хоёуланг нь mount** хийдэг тул `/admin/inventory`-д мөр

байв — 200 сав = 400 инпут, 400 диалог, яг тэр утсан дээр. Мөн эрэмбийн товч
хүснэгтийн толгойд байдаг тул **утсан дээр эрэмбэлэх боломж огт байхгүй**.
Картын жагсаалт нь нэргүй `<div>` овоо байв.

**Болгосон нь.**
- `useIsPhone()` (matchMedia) — карт **эсвэл** хүснэгтийн аль нэгийг л render
  хийнэ. Анхны render нь хүснэгт (бүрэн markup) тул JS ажиллаагүй ч бүх мөр
  ирнэ.
- Утсанд зориулсан **эрэмбийн Select** нэмэв — мөн л `setSorting`-ыг удирдана,
  `optgroup`-оор өсөх/буурахыг ялгана.
- Жагсаалтад `role="list"` + `aria-label`, карт бүрт `role="listitem"`.
