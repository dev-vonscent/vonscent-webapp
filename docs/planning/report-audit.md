### 1.1 Орлого (Борлуулалт)

```
place_order
  order_items.unit_price  ← variant_price() = coalesce(sale_price, price)  (0054a)
                            багцын мөрөнд хямдарсан үнэ (0028a); бэлэг = 0₮
  orders.subtotal         = Σ unit_price × qty          (sale + багцын хямдрал ОРСОН)
  orders.gross_subtotal   = Σ list_price × qty          (зөвхөн тайлбар, тайланд ороогүй)
  orders.discount         = ЗӨВХӨН купон (validate_coupon, row lock)
  orders.loyalty_used     = min(хүссэн, оноо × redeemRate, subtotal − discount)
  orders.total            = subtotal + shipping_fee − discount − loyalty_used
mark_order_paid → payment_status = 'paid'

ТАЙЛАН: revenue = Σ greatest(subtotal − discount − loyalty_used, 0)
        where payment_status = 'paid' and created_at ∈ [p_from, p_to]
```

- Хөнгөлөлт **давхар хасагдахгүй**: sale/багцын хямдрал `subtotal`-д аль
  хэдийн орсон, `discount` нь зөвхөн купон. (Тест B ✓)
- Хүргэлт ороогүй, купон/оноо хассан — шаардлагатай (`requirement_final.md`
  «Борлуулалт бодох арга») тохирно.
- Шүүлтүүр нь **`payment_status`** ба **`orders.created_at`** (захиалгын
  огноо — төлсөн огноо биш). `status`-ыг огт харахгүй.
- Бүлэглэлт `at time zone 'Asia/Ulaanbaatar'` (0074) — зөв. `p_from/p_to` нь
  `ubIso()`-оор `+08:00` авна.
- **top products / brands** = Σ `order_items.line_total` — купон, оноо
  хасаагүй (F3).
- **Export CSV «Борлуулалт»** = мөр бүр `orders.total` (хүргэлт орсон) (F2).
- **Print** = `getReportData`-тай ижил тоо (зөвхөн орлого, зардал/ашиг байхгүй).

### 1.2 Зардал

```
ТАЙЛАН: cost = Σ products.bottle_price   where products.created_at ∈ муж
             + Σ restock_log.cost        where restock_log.created_at ∈ муж
profit (JS) = revenue − cost
```

- Бараа үүсгэх (`api/admin/products/route.ts`) нь `bottle_price`,
  `bottle_ml`-ийг хадгалж, `inventory.on_hand_ml = onHandMl`-ийг шууд бичнэ —
  **restock_log мөр үүсэхгүй**. Зардалд ганц `bottle_price` орно, `onHandMl`
  хэд ч байсан.
- `restock_inventory(+delta, cost)` → `restock_log.cost` (нийт худалдан авсан
  үнэ). `−delta` (засвар) → route нь `cost = 0`-ийг албадна; RPC өөрөө
  `greatest(cost, 0)` — хасалт зардлыг **сөрөг болгохгүй, 0** (F12-ийг үз).
- **₮/ml нэгж өртөг хаана ч тооцогдохгүй.** COGS байхгүй — «ашиг» нь
  «мужийн борлуулалт − мужид хийсэн хөрөнгө оруулалт» (F1).
- `bottle_price`-ын түүх хадгалагдахгүй; засвар ретроактив (F10).

### 1.3 Буцаалт / цуцлалт

| Үйлдэл | Орлого | ml | Оноо | Купон |
|---|---|---|---|---|
| Төлөхөөс өмнө цуцлах (`update_order_status`) | 0 (paid биш) | `release_inventory` | ашигласан буцна | `used_count − 1`, redemption `cancelled_at` |
| Reserve timeout (`release_expired_reserves`) | 0 | release | буцна | буцна |
| Төлсний дараа цуцлах | **Тоологдсон хэвээр** (F4) | `on_hand + ml` | ашигласан буцна, олсон хасагдана (0-ээр хавчина) | буцна; урамшууллын купон устна/идэвхгүй |
| Цуцлагдсаны дараа refund | 0 (`refunded`) — **захиалгын сард ретроактив** (F6) | — | — | — |
| Хүргэгдсэний дараа refund (0094) | 0, ретроактив | **буцахгүй** (зориуд) | **хасагдахгүй** (F8) | урамшууллын купон **идэвхтэй үлдэнэ** (F8) |

- Refund нь **бүтэн, нэг төлөв**: `payment_status → 'refunded'`. Буцаасан дүн,
  огноо, хэсэгчилсэн буцаалт хадгалагдахгүй. Бодит шилжүүлэг =
  `total − 1%` (`src/lib/refund.ts`) (F5).
- Давхар refund: `for update` + `already` — хамгаалагдсан (K ✓).

### 1.4 V-point

- Олгох: `mark_order_paid` → `floor((subtotal − discount) / earnPer) × earnPoints`
  → `pending_points`, `available_at = хүргэх өдөр 00:00 УБ + lockHours` (0091).
  Хүргэгдмэгц шууд нээгдэнэ. **Оноогоор төлсөн хэсгээс ч оноо бодно** (F7).
- Цуцлалт: ledger-ээс net-ийг буцаана, 0-ээс доош хавчина (F9).
- Тайланд оноо нь зөвхөн `loyalty_used`-аар (орлого хасах) л ордог — зөв.

### 1.5 Spin wheel

- Оноо / купон шагнал → ашиглагдахад `loyalty_used` / `discount` болж
  орлогоос хасагдана — зөв.
- Багц (`bundle`) шагнал: `fulfilled_at`-ийг л тавина
  (`api/admin/lucky-wheel/route.ts:130`) — ml хасагдахгүй, зардал
  бүртгэгдэхгүй (F18).

**Шалгаад зөв гэж баталсан (олдвор биш):**

- Хөнгөлөлт давхар хасагдахгүй; `total = subtotal + shipping − discount − loyalty` бүх dev захиалгад үнэн.
- Мөнгө бүхэлдээ `int` / `bigint`; купоны хувь `floor`, оноо `ceil` — float алдаа байхгүй. PostgREST `bigint`-ийг JSON number-оор өгнө (2⁵³ хүртэл аюулгүй).
- УБ цагийн бүсийн бүлэглэлт (23:30, 00:10 УБ) зөв.
- `totals == Σ series` (dev сангийн бүх хугацаа ба тестийн мужуудад).
- Төлөхөөс өмнөх цуцлалт: reserve, купон, оноо бүрэн буцна.
- Давхар refund, давхар цуцлалт idempotent; зэрэг цуцлалт `for update`-аар хүлээнэ.
- Сөрөг засвар зардлыг сөрөг болгохгүй; `RESERVED_FLOOR` ажиллана; dev санд `0 ≤ reserved ≤ on_hand`, `reserved == төлөгдөөгүй захиалгын ml`.
- Status шилжилт (`auto_dispatch/deliver_orders`) `payment_status`-ыг хөндөхгүй тул орлогын шүүлтүүртэй зөрөхгүй (харин F4 нь `status`-ыг огт харахгүйгээс болж гарна).

## 3. Бизнесийн шийдвэр шаардлагатай асуултууд

5. **Q5 — Оноогоор төлсөн хэсгээс** шинэ оноо олгох уу? (F7)
6. **Q6 — Хүргэгдсэний дараах буцаалтад** олсон оноо болон 300k+ урамшууллын купоныг хураах уу? Хэрэглэгч оноогоо аль хэдийн зарцуулсан бол сөрөг үлдэгдэл/өр бүртгэх үү? (F8, F9)

## 5. Шийдвэр ба хэрэгжүүлэлт (2026-10-01)

### 5.1 Клиент/хөгжүүлэгчийн тохиролцоо

- **Цэвэр борлуулалт** нь хөгжүүлэгчийн сарын хөлсний суурь (12%). Хөлсийг
  тайлан бодохгүй — хэрэглэгч энэ тооноос өөрөө бодно.
  `= барааны дүн − купон − V-point − тухайн мужид хийгдсэн буцаалт`. Хүргэлт огт орохгүй.
- **Ашиг**-ийг клиент өөрөө харна.
  `= цэвэр борлуулалт − QPay шимтгэл (нийт дүнгийн 1%) − барааны худалдан авалт + буцаалтаас суутгасан шимтгэл`.
  - Купон, V-point зардлын мөр болж харагдана — «барааны нийт дүн»-гээс
    хасагдана. Нэг удаа л хасагдах тул давхар хасалт үүсэхгүй.
  - Хүргэлтийн төлбөр дансанд орох ч клиент тэр чигээр нь хүргэлтийн
    компанид төлдөг — тооцоонд орохгүй, зөвхөн мэдээлэл болж харагдана.
  - Хөгжүүлэгчийн 12% ашгийн тайланд орохгүй.
- **Буцаалт буцаасан сардаа хасагдана** — өнгөрсөн (цалин бодогдсон) сарын тоо өөрчлөгдөхгүй.
- Хугацааны мужаар шүүнэ (одоо байгаа шүүлтүүр).

**Хариулт шаардлагагүйгээр авсан таамаглал** (буруу бол хэлээрэй):

- QPay шимтгэл нь зөвхөн `payment_method = 'qpay'` захиалгад, `orders.total`-оос (хүргэлт орсон). Банкны шилжүүлэгт 0.
- Цуцлагдсан, төлсөн захиалга мөнгө нь буцаагдах хүртэл борлуулалтад тоологдоно (мөнгө дансанд байгаа), «буцаалт хүлээж буй» гэж тусад нь харагдана (F4 → шийдэгдсэн).
- Буцаалтын 1% суутгал зөвхөн **цуцлагдсан** захиалгын буцаалтад (админы захиалгын хуудасны харуулдаг дүн). Хүргэгдсэний дараах буцаалт бүтэн дүнгээр.
- Барааны худалдан авалт = эх савны үнэ (бараа үүсгэсэн өдөр) + restock-ийн үнэ (бүртгэсэн өдөр) — шаардлагын «Борлуулалт бодох арга»-тай ижил. COGS (₮/ml) тооцохгүй (F1 → шийдэгдсэн).
- Эх савны үнийг засах нь анх бичсэн үнийн алдааг засах гэж тооцогдоно (ретроактив хэвээр).
- Орлого захиалга **үүссэн** огноогоор (төлбөр 35 минутын дотор төлөгддөг тул төлсөн огноотой бараг ижил).

- **F8** — Хүргэгдсэний дараах буцаалт цуцлалттай ижил (0112, 0113): хэрэглэгчийн **ашигласан** V point ба купон буцна, **олсон** V point ба урамшууллын купон хүчингүй болно.
