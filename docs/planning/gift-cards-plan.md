## 0. Товч

Хэрэглэгч 100,000 / 200,000 / 300,000 / 500,000₮-ийн бэлгийн карт худалдаж
авна. Загвар сонгоод мэндчилгээ, «хэнээс» гэдгийг бичиж, хүлээн авагчийн
имэйлийг оруулна. Төлбөр төлөгдмөгц систем давтагдашгүй код үүсгэж,
хүлээн авагч руу имэйлээр илгээнэ. Хүлээн авагч бүртгүүлээд кодоо оруулахад
картын дүн **V point** болж дансанд нь орно (1 оноо = 1₮). Код 1 жилийн
хугацаатай; оноо болсны дараа хугацаагүй.

Карт бол **нөөцгүй, хүргэлтгүй дижитал бараа**. Захиалга, QPay, буцаалт,
тайлангийн одоогийн дэд бүтцийг (`orders`) дахин ашиглана, гэхдээ карт
худалдан авалт нь тусдаа урсгалтай байна (§4.1).

## 2. Хэрэглэгчийн урсгал

### 2.1 Худалдан авагч

```
/gift-cards
  ① Загвар сонгох (8 загвар, carousel/grid)
  ② Дүн сонгох (4 chip)
  ③ Хүлээн авагчийн нэр, мэндчилгээ (120 тэмдэгт), «Хэнээс»
  ④ Хэрхэн өгөх вэ?
       ○ Имэйлээр одоо илгээх        → хүлээн авагчийн имэйл
       ○ Тодорхой өдөр илгээх        → имэйл + огноо (төрсөн өдөр г.м.)  [§10 санаа, v1-д орж болно]
       ○ Өөрөө өгнө                  → код зөвхөн миний бүртгэлд; холбоос хуулах / зураг татах / дараа нь имэйлээр илгээх
  ⑤ Баруун талд (mobile-д дээр) картын live preview
  ⑥ «Төлбөр төлөх» → QPay → амжилттай хуудас
```

- **Нэвтрэлт шаардана** (санал, §12-Q1): худалдан авагч оноо авах (K12),
  картаа бүртгэлээсээ удирдах, дахин илгээх боломжтой байх.
- Нэг захиалгад 1 карт (v1). Олон карт хэрэгтэй бол дахин хийнэ — урсгал
  энгийн, захиалга бүр нэг хүлээн авагчтай.
- Амжилттай хуудас: «Карт Сараа руу илгээгдлээ» эсвэл «Картаа хэрхэн өгөх вэ»
  (холбоос хуулах, Messenger-ээр хуваалцах, PNG татах, имэйлээр илгээх).

### 2.2 Дараа нь захиалга дотроос илгээх

`/account/orders/[id]` (карт захиалга) ба `/account/gift-cards`:

- Картын төлөв: **Илгээгээгүй · Илгээсэн · Оноо болгосон · Хугацаа дууссан · Цуцлагдсан**
- «Имэйлээр илгээх» (илгээгээгүй/илгээсэн боловч ашиглаагүй үед):
  имэйл оруулна, мэндчилгээг засаж болно.
- «Дахин илгээх» — 5 минутад 1, нийт 5 удаа (spam хамгаалалт).
- «Холбоос хуулах», «Зураг татах» (хэвлэж эсвэл Messenger-ээр өгөх).
- Оноо болгосон бол «Сараа 11/12-нд ашигласан» гэж харагдана (код нуугдана).

### 2.3 Хүлээн авагч (манай сайтыг мэдэхгүй байх магадлал өндөр)

```
Имэйл / Messenger холбоос / QR
  → /gift/<token>                    (нэвтрэлтгүй нээгдэнэ)
       Картын том зураг, мэндчилгээ, дүн, «Болдоос»
       [ Бэлгээ авах ]               ← ганц том товч
       3 алхамын заавар + FAQ
  → Нэвтрээгүй бол: утасны дугаараар бүртгүүлэх (verify.mn SMS) → буцаад /gift/<token>
  → «100,000 V point-ийг дансандаа нэмэх үү?» [ Тийм ] (давхар дарахаас хамгаална)
  → Амжилт: «Таны дансанд 100,000 V point орлоо»
       [ Үнэртэн сонгох ]  [ Үнэрээ олох (quiz) ]
       «Төлбөр төлөхдөө V point ашиглах»-ыг сонгоход хямдарна гэж зурагтай тайлбар
```

- Код гараар оруулах зам: `/account/loyalty` дээд хэсэгт «Бэлгийн код
  оруулах» талбар, мөн `/gift-cards/redeem`.
- Token (холбоос) ба код хоёр тусдаа: token нь 128-bit, холбоост; код нь
  хэвлэх, гараар бичихэд (`VON-XXXX-XXXX`).

## 4. Сервер логик

### 4.1 Захиалга үүсгэх — `place_gift_card_order(p_user, p_card jsonb)`

`place_order` (0149, 1400 мөр) руу салаа нэмэхгүй — тусдаа жижиг RPC:

- `if not feature_enabled('gift_cards') then raise 'FEATURE_DISABLED'`.
- Нэвтэрсэн хэрэглэгч, дүн K1-д, загвар идэвхтэй.
- `orders`: `order_type='gift_card'`, `subtotal=amount`, `shipping=0`,
  `discount=0`, `loyalty_used=0`, `total=amount`, хүргэлтийн талбарууд null,
  `payment_method='qpay'`.
- `order_items`: `line_kind='gift_card'`, `unit_price=amount`, `qty=1`.
- `gift_cards`: `status='pending'`, код/token энд үүснэ (төлөгдөөгүй бол ашиглагдахгүй).
- Route: `POST /api/gift-cards/orders` — Zod, `enforceRateLimit("order")`,
  idempotency (`claimOrderRequest`), дараа нь `ensureInvoice` (QPay).

Тусдаа route байх нь checkout хуудас (2000+ мөр) болон сагсанд хүрэхгүй
гэсэн үг. Сагсанд карт + үнэртэн хамт (§12-Q2) v2 болно.

### 4.2 Захиалгын төлөв

`order_type='gift_card'` захиалга төлөгдмөгц `delivered` болно (хүргэлт
байхгүй). Хүргэлтийн самбар, курьерийн жагсаалт, `deliver_on`-ийн
тооцоолол `order_type='goods'`-оор шүүнэ.

### 4.3 Төлбөр баталгаажих — `mark_order_paid`

Бүх төлбөрийн зам (webhook, status, reconcile, admin гараар) энд нэгддэг
тул **код идэвхжүүлэлт DB дотор, атомаар**:

```sql
update gift_cards set status='active', issued_at=now(),
       expires_at = now() + interval '1 year'
 where order_id = p_order and status='pending';
```

Имэйл илгээлт TS талд, `confirm-order.ts` `commit()`-ийн дараа
(`sendOrderCustomerEmail`-ийн хажууд) `deliverGiftCards(orderId)`:
`sent_at is null and recipient_email is not null and (send_at is null or send_at <= now())`
нөхцөлтэй, илгээсний дараа `sent_at` тавина → webhook + reconcile давхар
дуудагдсан ч нэг л имэйл. Амжилтгүй бол cron дахин оролдоно (§6.4).

### 4.4 Худалдан авагчийн оноо (K12)

`mark_order_paid`-ийн одоогийн earn логик (`tier_rate_for_spend`, 0143)
картын захиалгад ч ажиллана: 500,000₮ карт × 3% = 15,000 оноо.

- `available_at`: хүргэлт байхгүй тул `paid_at + lockHours`.
- **Буцаалтаас хамгаалах санал:** картын оноо тухайн карт `redeemed`
  болох эсвэл 14 хоног өнгөрөхөд нээгдэнэ (§12-Q4). Эс тэгвээс: карт авна →
  оноо нээгдэнэ → оноогоо зарцуулна → картаа буцаалгана.
- **Зэрэглэлийн зарцуулалт** (`user_lifetime_spend`): картын захиалгыг
  **оруулахгүй** гэж санал (§12-Q3). Учир нь хүлээн авагч тэр мөнгөөр
  бараа авахад дахин тоологдоно; өөртөө карт авбал давхар тоологдоно.

### 4.5 Оноо болгох — `redeem_gift_card(p_user, p_code_or_token)`

`claim_profile_reward` (0163)-ийн загвараар, security definer, service role:

```sql
if not feature_enabled('gift_cards') then raise 'FEATURE_DISABLED'; end if;
select * into v_card from gift_cards
 where code = upper(p_code) or token = p_token for update;
-- NOT_FOUND / ALREADY_REDEEMED / EXPIRED / VOID
update gift_cards set status='redeemed', redeemed_by=p_user, redeemed_at=now() ...;
update profiles set loyalty_points = loyalty_points + v_card.amount where id = p_user;
insert into loyalty_ledger (user_id, order_id, delta, reason, released)
values (p_user, v_card.order_id, v_card.amount, 'gift_card', true);
```

- Оноо **шууд** ашиглагдах боломжтой (lock-гүй) — бэлэг бол мөнгө.
- Худалдан авагч өөрөө өөрийнхөө картыг redeem хийж болно (өөртөө урьдчилгаа).
- `redeemRate` 1 биш болбол: оноо = `amount / redeemRate`. Одоо 1.
- Route `POST /api/gift-cards/redeem` — нэвтрэлт, Zod, rate limit (§8).

### 4.6 Цуцлалт ба буцаалт

- `active` (ашиглаагүй) карт → буцаалт зөвшөөрнө: `status='void'`, худалдан
  авагчийн earn оноо `reverse_order_loyalty`-ээр буцна, token/код ажиллахаа больно.
- `redeemed` карт → **буцаалтгүй** (оноо аль хэдийн хүлээн авагчийн дансанд).
  Admin UI-д товч идэвхгүй + тайлбар. Онцгой тохиолдолд admin гараар.
- `mark_order_refunded`, `update_order_status('cancelled')`-д gift_card салаа.

### 4.7 Хугацаа (pg_cron, өдөр бүр 09:00 УБ)

- `expires_at <= now()` ба `active` → `expired`.
- Сануулга: 30 хоног, 7 хоногийн өмнө хүлээн авагч руу (имэйл байгаа бол),
  ашиглагдаагүй бол 7 хоногийн дараа нэг удаа «Бэлгээ аваагүй байна» имэйл.
- Бүгд `if not feature_enabled('gift_cards') then return; end if;`

- Preheader: `100,000₮-ийн үнэртний бэлэг таныг хүлээж байна`
- Бүтэц:
  1. Картын зураг (600px, §5.3)
  2. «Сараа танд,» + мэндчилгээ (худалдан авагчийн бичсэн)
  3. **[ Бэлгээ авах ]** CTA → `/gift/<token>`
  4. «Эсвэл кодоо гараар оруулна уу»: `VON-7K4P-Q9XM`
  5. Хэрхэн ашиглах вэ — 3 алхам:
     1. «Бэлгээ авах» дээр дарна (эсвэл QR уншуулна)
     2. Утасны дугаараараа бүртгүүлнэ — SMS-ээр баталгаажна
     3. 100,000 V point дансанд орно. Үнэртэн сонгоод төлбөр төлөхдөө
        «V point ашиглах»-ыг сонгоно (1 оноо = 1₮)
  6. QR (утсаар уншуулах — имэйлийг компьютер дээр нээсэн үед)
  7. «Код 2027-11-10 хүртэл хүчинтэй. Оноо болгосны дараа хугацаагүй.»
  8. Холбоо барих (утас, Facebook, Instagram)
- QR: `qrcode` package, `GET /api/gift-cards/[token]/qr.png` (cache-тэй).

### 6.2 Худалдан авагчид

- Төлбөр баталгаажсан: «Бэлгийн карт Сараа (sa…@gmail.com) руу илгээгдлээ»
  + картын зураг + «Захиалгаас дахин илгээх, холбоос хуулах» холбоос.
  «Өөрөө өгнө» сонгосон бол: «Картаа хэрхэн өгөх вэ» 3 сонголт.
- Хүлээн авагч ашигласан үед: «Сараа таны бэлгийг хүлээн авлаа» (§10 санаа).

### 6.3 Сануулга (cron)

- 7 хоног ашиглаагүй: «Таны бэлэг хүлээж байна».
- Хугацаа дуусахаас 30 / 7 хоногийн өмнө.

### 6.4 Найдвартай байдал

- `EMAIL_FROM` dev/prod хоёуланд `@vonscent.mn` — домэйн Resend-д
  баталгаажсан эсэхийг (SPF/DKIM) launch-аас өмнө шалгана.
- Илгээлт амжилтгүй бол `sent_at` null хэвээр → 15 минутын cron дахин
  оролдоно (`send_count` ≤ 5), бүтэлгүйтвэл admin мэдэгдэл.
- Худалдан авагч имэйлийг буруу бичсэн бол: ашиглаагүй үед бүртгэлээсээ
  засаад дахин илгээнэ (хуучин token хүчинтэй хэвээр — дамжуулсан холбоос ажиллана).

## 7. Тайлан (орлого / зарлага)

### 7.1 Клиентийн дүрэм → томьёо

Одоогийн тохиролцоо (report-audit §5.1):
`Цэвэр борлуулалт = барааны дүн − купон − V-point − буцаалт`

Карт нэмэгдсэний дараа:

```
  Барааны нийт дүн               (үнэртэн + нэмэлт бараа; карт ОРОХГҮЙ)
+ Бэлгийн карт                    (K9: зарагдсан сардаа бүтэн дүнгээр)
− Купон
− V-point                         (K10: оноогоор төлсөн хэсэг — зарлага)
− Буцаалт                         (карт буцаалт орно)
= Цэвэр борлуулалт
```

Жишээ: 11-р сард 100,000₮ карт зарагдав, 12-р сард хүлээн авагч
120,000₮-ийн үнэртэн авч 100,000-ыг оноогоор, 20,000-ыг QPay-ээр төлөв.

| Сар | Барааны дүн | Карт | V-point | Цэвэр борлуулалт | Дансанд орсон мөнгө |
|-----|------------:|-----:|--------:|-----------------:|-------------------:|
| 11 | 0 | 100,000 | 0 | 100,000 | 100,000 |
| 12 | 120,000 | 0 | −100,000 | 20,000 | 20,000 |
| Нийт | | | | **120,000** | **120,000** |

Мөнгөн урсгалтай яг таарч, давхар тоологдохгүй. V-point мөр нь картаас
гадна энгийн оноо (earn, review, spin)-г ч хамарна — клиентийн «ер нь бүх
төрлийн оноо» гэсэнтэй нийцнэ.

### 7.2 Нэмэлт мэдээллийн мөр (тооцоонд орохгүй)

- **Ашиглагдаагүй картын үлдэгдэл** — `active` картуудын нийлбэр (өр төлбөр).
- **Хугацаа дууссан карт** — тухайн мужид `expired` болсон дүн (аль хэдийн
  орлогод орсон тул нэмж тооцохгүй, зөвхөн мэдээлэл).
- Зарагдсан / ашиглагдсан картын тоо, дундаж дүн, загвар бүрээр.

### 7.3 Хэрэгжүүлэлт

- `admin_report_events`: `line_kind='gift_card'` дүнг `gift_card_sales`
  тусдаа баганаар; `goods`-оос хасна (үнэртний bucket = subtotal − extras − gift_card).
- `admin_report_finance`, `FinanceRow`, `financeLines()` (report-finance.ts),
  `finance-breakdown.tsx`: «Бэлгийн карт» мөр.
- Top бараа / брэнд — `line_kind='perfume'` шүүлттэй тул нөлөөгүй.
- QPay шимтгэл картад ч бодогдоно (`orders.total`) — одоогийн логик хэвээр.
- CSV экспорт (`/api/admin/reports/export`): `order_type`, `gift_card` багана.
- `scripts/test-reports.ts`-д дээрх жишээг SQL тест болгоно.

## 8. Аюулгүй байдал

- **Код brute force:** 32^8 ≈ 1.1×10¹² хувилбар. Redeem rate limit:
  хэрэглэгчээр 5 / 10 мин, IP-ээр 20 / цаг (`RATE_LIMITS.giftCardRedeem`).
  Буруу оролдлого 10 хүрвэл хэрэглэгчийг 24 цаг хаана.
- `/gift/[token]` — 128-bit token, `noindex`, `Referrer-Policy: no-referrer`.
  Нэвтрэлгүй хуудас нь зөвхөн зураг/мэндчилгээ/дүнг харуулна, **код биш**.
- Redeem: `for update` түгжээ → давхар дарсан ч нэг л удаа оноо орно.
- Худалдан авагчийн оноо зөвхөн карт төлөгдсөний дараа, буцаалтад буцна (§4.4).
- Имэйлийн мэндчилгээ HTML escape (`renderEmail` текст талбар).
- Admin бүх үйлдэл `admin_audit`-д (дахин илгээх, имэйл засах, цуцлах).

## 9. Дизайн

### 9.1 Карт (canvas)

Canvas-д 00 safe zone + 8 загвар: Үндсэн, Төрсөн өдөр, Хайртай хүндээ,
Баярлалаа, 3-р сарын 8, Шинэ жил, Цагаан сар, Багш нарын баяр.

Safe zone (систем текстийг өөрөө тавина):

2. Дүн + «= 100,000 V point» — баруун дээд
3. Гарчиг (2 мөр), «Сараа танд,», мэндчилгээ (3 мөр, 120 тэмдэгт) — зүүн дунд
4. ~~Код~~ → зураг дээр код гаргахгүй (§5.3); энэ бүсэд «vonscent.mn/gift» эсвэл хоосон
5. Илгээгч — баруун доод
6. Чимэглэл — баруун дунд 380×440

**Анхаарах:** canvas-ийн загварууд ягаан `#c2245c` + хар өнгөтэй, харин
брэнд өнгө нь navy `#0E1B3B` (design.md §2). Үндсэн загвар навигаци,

### 9.2 Зургийг тусад нь үүсгэх үү? — **Тийм, санал болгоно**

Та (эсвэл дизайнер) **зөвхөн дэвсгэр** зургийг үүсгээд өгнө, текстийг систем
давхарлана:

- 8 загвар × `2400×1512` PNG/WebP, ≤300KB, **текстгүй** (нэр, дүн, код, мессеж бичихгүй).
- Чимэглэл зөвхөн чимэглэлийн бүсэд; бусад талбайд бүдэг хээ л байж болно.
- Gradient хэрэглэхгүй (design.md).
- Загвар бүрт: үндсэн текстийн өнгө, бүдэг текстийн өнгө, гарчгийн текст
  (жишээ нь «Төрсөн өдрийн мэнд хүргэе!»), санал болгох мэндчилгээ.
- Хүлээлгэн өгөх хэлбэр: `gift-card-<id>@2x.png` + хүснэгт (өнгө, гарчиг).
  Admin «Загвар» хуудаснаас оруулна, эсвэл анхны 8-ыг seed script-ээр.

Яагаад: текстийг зураг дээр шатаавал нэр/дүн/мэндчилгээ бүрээр зураг
хэрэгтэй болно; дэвсгэр + систем текст бол 8 зураг хангалттай, засвар
хялбар, кирилл үсэг тод.
