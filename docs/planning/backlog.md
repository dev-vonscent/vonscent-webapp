## 0. 2026-09-02-ны шийдвэрүүд (шинэ backlog-ийн зөрчлийг шийдсэн)

Шинэ шаардлага нь хэрэгжсэн логиктой зөрчилдсөн 4 цэгийг клиенттэй тодруулав:

| # | Зөрчил | Шийдвэр |
|---|---|---|
| 1 | Одоогийн хямдрал нь **зөвхөн харагдац** (төлөх үнэ өөрчлөгддөггүй, зураастай «хуучин үнэ»-г зохиомлоор боддог) | **Бодит хямдрал руу шилжинэ.** Хэмжээ (variant) тус бүр өөрийн хямдралтай, төлөх үнэ бодитоор буурна. Хуучин барааны түвшний «үзүүлэн» хямдрал устана |
| 2 | **Хоёр өөр бэлгийн систем** зэрэг ажиллаж байсан: (а) багц бүрийн дагалдах бэлэг — дэлгүүрийн дурын үнэрээс, (б) сарын pool-оос 200K тутамд 1мл | **Нэг pool болж нэгдэнэ.** Бүх бэлэг зөвхөн админы сонгосон **6–8 үнэрийн pool**-оос гарна. Pool хоосон бол бэлгийн сонголт унтарна. Pool-ыг **сар бүр солих албагүй** — админ хүссэн үедээ солино |
| 3 | Багцын баталгаат бэлэг ба дүнгийн бэлэг хэрхэн нийлэх | **Ихийг нь авна** (нэмэхгүй): `эрх = max(багцын баталгаа, ⌊цэвэр дүн ÷ 200,000⌋)`. Жишээ: 10мл багц 450K → **2** |
| 4 | Урьдчилсан захиалга vs «бүх захиалга маргааш 11:00-д гарна» гэсэн автомат хуваарь | Захиалгад **«хүргэх өдөр»** талбар нэмнэ. Автомат төлөв шилжилт зөвхөн тухайн өдөр нь ажиллана, цуцлалт нь **хүргэх өдрийн 9:00 хүртэл**. Нөөцийн одоогийн дүрэм (30 мин reserve timeout) хэвээр |

**Бэлгийн эцсийн дүрэм (нэгтгэсэн):**

```
цэвэр дүн = барааны дүн − купоны хямдрал      (хүргэлт, оноо ороогүй)
дүнгийн эрх = ⌊цэвэр дүн ÷ 200,000⌋           ← дан бараа авсан ч бодогдоно

багцын баталгаа:
  preset 5 / 10 / 20мл багц → 1
  preset 2мл багц          → 0
  custom багц              → 0
  (олон багц бол баталгаанууд нь нэмэгдэнэ)

эрх = max(багцын баталгаа, дүнгийн эрх)
бэлэг = pool доторх үнэрээс 1мл, эрхийн тоогоор
```

Жишээ: дан 4 ус 190K → 0 · дан 4 ус 210K → 1 · custom багц 150K → 0 ·
custom багц 420K → 2 · preset 2мл багц 150K → 0 · preset 10мл багц 150K → 1 ·
preset 10мл багц 450K → 2.

### 3.1 Автомат купон — шалгалтын үр дүн (2026-09-13)

**Ажиллаж байна.** Эхний шалгалтад «код нь огт байхгүй» гэж дүгнэсэн нь
**буруу байсан**: TypeScript талаас `autoGrant`-ыг хайхад зөвхөн админы форм
олдсон боловч бодит хэрэгжилт нь **Postgres talд** байсан —

- `grant_reward_coupon(p_order)` (0025, дүрмээ 0041-д зассан),
- `orders_reward_coupon` **trigger** нь `orders.payment_status` нь `'paid'`
  болох мөчид түүнийг дуудна.

Прод дээрх сангаас авсан dump-аар багана, функц, trigger гурвуулан байгааг
**баталсан**.

**Дүрэм (0041-ийн код яг юу хийдэг):**

```
цэвэр дүн = greatest(orders.subtotal − orders.discount, 0)   ← хүргэлт, оноо ОРООГҮЙ
нөхцөл   = payment_status → 'paid' болов
         ∧ orders.user_id тэг биш (зочинд ҮГҮЙ)
         ∧ settings.coupons.autoGrant.enabled
         ∧ цэвэр дүн ≥ autoGrant.minTotal (өгөгдмөл 300,000)
         ∧ тухайн захиалгад купон урьд өмнө үүсээгүй
```

Купон нь `user_id`-тай (зөвхөн тэр хүн ашиглана, `validate_coupon` бусдад
«олдсонгүй» гэнэ), `max_uses_per_user` = тохиргооных, хугацаа нь
`validDays` хоног. Нэг захиалга = нэг купон — `coupons.source_order_id` дээрх
цорын ганц индекс (0025) баталгаажуулна.

**Дутуу байсан ганц зүйл, түүнийг нөхсөн (2026-09-13):** купон үүссэн ч
худалдан авагчид **хэлдэггүй** байв — зөвхөн дансны «Миний купон» хэсэгт
чимээгүй нэмэгддэг, хэн ч тэр хуудсыг зориуд шалгахгүй. Одоо баталгаажсан
захиалгын имэйлд «🎁 Танд дараагийн захиалгад зориулсан … купон нэмэгдлээ:
КОД, … хүртэл хүчинтэй» гэсэн мөр нэмэгдэнэ
(`src/lib/notify/customer-email.ts`). Өөр код өөрчлөгдөөгүй, шинэ migration
шаардлагагүй.

**Одоогийн тохиргоо:** `enabled` унтраалттай. Админ Тохиргоо → «Автомат
купон» хэсгээс босго/хувь/хугацааг бичээд асаахад л ажиллаж эхэлнэ.
Талбарын нэр «Барааны доод дүн» бөгөөд доор нь аль дүнг тоолохыг бичсэн.
