## 0. 2026-09-02-ны шийдвэрүүд (шинэ backlog-ийн зөрчлийг шийдсэн)

Шинэ шаардлага нь хэрэгжсэн логиктой зөрчилдсөн 4 цэгийг клиенттэй тодруулав:

| # | Зөрчил | Шийдвэр |
|---|---|---|
| 1 | Одоогийн хямдрал нь **зөвхөн харагдац** (төлөх үнэ өөрчлөгддөггүй, зураастай «хуучин үнэ»-г зохиомлоор боддог) | **Бодит хямдрал руу шилжинэ.** Хэмжээ (variant) тус бүр өөрийн хямдралтай, төлөх үнэ бодитоор буурна. Хуучин барааны түвшний «үзүүлэн» хямдрал устана |
| 2 | **Хоёр өөр бэлгийн систем** зэрэг ажиллаж байсан: (а) багц бүрийн дагалдах бэлэг — дэлгүүрийн дурын үнэрээс, (б) сарын pool-оос 200K тутамд 1мл | **Нэг pool болж нэгдэнэ.** Бүх бэлэг зөвхөн админы сонгосон **6–8 үнэрийн pool**-оос гарна. Pool хоосон бол бэлгийн сонголт унтарна. Pool-ыг **сар бүр солих албагүй** — админ хүссэн үедээ солино |
| 3 | Багцын баталгаат бэлэг ба дүнгийн бэлэг хэрхэн нийлэх | **Ихийг нь авна** (нэмэхгүй): `эрх = max(багцын баталгаа, ⌊цэвэр дүн ÷ 200,000⌋)`. Жишээ: 10мл багц 450K → **2** |
| 4 | Урьдчилсан захиалга vs «бүх захиалга маргааш 11:00-д гарна» гэсэн автомат хуваарь | Захиалгад **«хүргэх өдөр»** талбар нэмнэ. Автомат төлөв шилжилт зөвхөн тухайн өдөр нь ажиллана, цуцлалт нь **хүргэх өдрийн 9:00 хүртэл**. Нөөцийн одоогийн дүрэм (30 мин reserve timeout) хэвээр |

**Бэлгийн эцсийн дүрэм (нэгтгэсэн):**

```
цэвэр дүн = барааны дүн − купоны хямдрал      (хүргэлт, оноо ороогүй)
дүнгийн эрх = ⌊цэвэр дүн ÷ 200,000⌋           ← дан бараа авсан ч бодогдоно

багцын баталгаа:
  preset 5 / 10 / 20мл багц → 1
  preset 2мл багц          → 0
  custom багц              → 0
  (олон багц бол баталгаанууд нь нэмэгдэнэ)

эрх = max(багцын баталгаа, дүнгийн эрх)
бэлэг = pool доторх үнэрээс 1мл, эрхийн тоогоор
```

Жишээ: дан 4 ус 190K → 0 · дан 4 ус 210K → 1 · custom багц 150K → 0 ·
custom багц 420K → 2 · preset 2мл багц 150K → 0 · preset 10мл багц 150K → 1 ·
preset 10мл багц 450K → 2.

## 1. Клиентийн шинэ backlog (2026-09-02)

### A. Багц / бэлгийн логик 🔵🔴

- [ ] **A1. Бэлгийн эрхийн томьёог дээрх дүрмээр дахин бичих.** Одоогийн логик
      «багц бүр = дор хаяж 1 эрх» гэж багцын хэмжээ, төрлийг үл хардаг. Шинэ
      дүрэмд custom багц ба 2мл preset багц баталгаат эрх өгөхөө болино.
      Сервер тал (захиалга бүртгэх RPC) заавал дахин тооцоолж шалгана — браузарын
      хэлснээр бэлэг олгож болохгүй.
- [ ] **A2. Бэлгийн pool-ыг цорын ганц эх сурвалж болгох** — багцын «дурын үнэрээс
      сонгох» дагалдах бэлгийг устгаж, бүх бэлгийн сонголтыг pool-оор хязгаарлана.
      Багцын дэлгэрэнгүй, custom угсрагч, checkout гурвуулаа нэг pool уншина.
      Pool хоосон / унтраалттай үед бэлгийн сонголт бүхэлдээ disable.
- [ ] **A3. Pool-ын хэмжээ 4–8 → 6–8** болгож админы хуудсанд заавар, шалгалтыг засах.
      «Сарын бэлэг» гэсэн нэршлийг «Бэлгийн үнэрүүд» болгож солино (сар бүр солих
      үүрэггүй болсон тул).
- [ ] **A4. Багцын бэлгийн тохиргоог цэгцлэх** — багц бүрийн `gift_ml` override
      болон глобал `giftMl` одоо 1–2мл байж болдог. Шинэ дүрэмд бэлэг үргэлж
      **1мл** тул илүүдэл тохиргоог авах эсэхийг шийдэх (хэрэглэгчийн UI-д
      «1мл sample» гэж тогтмол бичигдэнэ).

### B. Үнэ / хямдрал 🔵🔴

- [ ] **B1. Хэмжээ тус бүрийн хямдрал** — бараа үүсгэх/засах хуудсанд 2/5/10/20мл
      мөр бүрийн ард хямдралын талбар. Хямдрал нь **төлөх үнийг бодитоор**
      бууруулна (одоогийн «зөвхөн харагдац» загварыг орлоно).
- [ ] **B2. Хуучин барааны түвшний үзүүлэн хямдралыг устгах** — өгөгдлийг шинэ
      талбар руу нүүлгэж, хуучин баганыг хасах.
- [ ] **B3. Сервер талын үнийг цэгцлэх** 🔴 — сагс, захиалга бүртгэх RPC,
      багцын үнэ, борлуулалтын тайлан бүгд хямдарсан үнээр тооцно. Браузараас
      ирсэн үнэд хэзээ ч итгэхгүй (одоогийн зарчим хэвээр).
- [ ] **B4. Хэрэглэгчийн харагдац** — зөвхөн үндсэн үнэ (зураастай) ба хямдарсан
      үнэ. **Хувь харагдахгүй.** Одоогийн `−20%` badge-ийг авна (энэ нь өмнөх
      UI/UX аудитын шийдэлтэй зөрчилдөж байгааг клиент баталсан).
- [ ] **B5. Custom багц** хямдарсан үнээр тооцно (B3-ийн дараа автоматаар биелнэ,
      тестээр баталгаажуулна).
- [ ] **B6. Preset багцын үнэ тогтмол** 🔵 — багцад **админы бичсэн тогтмол үнэ**
      нэмнэ. Одоо багцын үнэ нь гишүүдийн үнийн нийлбэрээс хувь хасаж **амьдаар**
      бодогддог тул доторх барааны хямдрал багцын үнийг өөрчилнө — энэ нь шинэ
      шаардлагатай зөрчилдөж байна. Тогтмол үнэ = эцсийн үнэ; гишүүдийн үнэ
      зөвхөн «хэмнэлт»-ийг харуулахад ашиглагдана.

- [ ] **Тайланг дурын огнооны мужаар харах** (одоо зөвхөн сараар).

### 2.5 Шинэ том функцууд

### 2.6 Техник / чанар

- [ ] **Хүртээмжийн (a11y) шалгалт** — сэрэмжлүүлэх цонхны зөв үүрэг, гарын

- [ ] **Устгагдсан баримтын лавлагааг кодын тайлбараас цэвэрлэх** —
      кодын комментууд одоо байхгүй файлуудыг заасаар байна.

      нийцүүлж засах эсвэл кодыг цэвэрлэх — аль нэгийг сонгох.
- [ ] **Дизайн системийн цэгцлэл** — давхардсан хоосон төлөв (18), хуудасны
      толгой (26 файл), тоолуур badge (8) — нэгдсэн компонент болгох.

### 2.7 Мэдэж байх зүйлс (засвар шаардаагүй, шийдвэр гарвал өөрчлөгдөнө)

- Төлөгдөөгүй захиалга автомат хүргэлтэд гардаггүй — нөөцөө 30 минутад сулруулаад
  үлддэг (шилжүүлгийн урсгал хийгдэх үед эргэж харна).
- Popup-ийн купоны код нь бодит купонтой тулгагддаггүй — админ гараар зөв бичих
  ёстой (G2-оор устах магадлалтай).
- Ашгийн тайлангийн зардал нь зарагдаагүй барааны эх савны үнийг ч тоолдог —
  «нийт хөрөнгө оруулалт vs борлуулалт» гэсэн утгатай.
- Тохиргоо хадгалахад super_admin эрх шаардана — operator бэлгийн pool-ыг
  хадгалж чадахгүй (зориудын хязгаарлалт).
