## B. DB migration шаардах ажлууд 🔵

### B1. Эрсдэлтэй алдаа
- [x] **Захиалга цуцлахад V point буцаах / хасах** — `0019_cancel_reversal.sql`.
      `loyalty_ledger`-ээс тухайн захиалгын цэвэр дүнг уншиж яг эсрэгээр нь
      буцаана (settings-ээс дахин тооцохгүй тул хооронд нь ханш өөрчлөгдсөн ч
      зөрөхгүй). Дахин цуцлахад давхар ажиллахгүй (`cancel_reverse` мөр шалгана).
      Хамт зассан: (1) **төлбөр төлөгдсөн** захиалга цуцлахад ml нь `on_hand`-д
      буцаж нэмэгдэнэ (өмнө нь байхгүй reserve-ийг «суллаж» бараа алдагдаж
      байсан), (2) `release_expired_reserves()` мөн энэ замаар цуцална.
- [x] **Профайл дээрх купоны жагсаалтыг хязгаарлах** — `0020_user_coupons.sql`:
      `coupons.user_id` + RLS (нийтийн ба өөрийн купон л харагдана).
      `validate_coupon(p_code, p_subtotal, p_user)` эзэмшигчийг шалгана —
      бусдын код `NOT_FOUND` буцаана (байгааг нь ч мэдэгдэхгүй).
      `place_order` купоныг худалдан авагчийн нэрээр шалгана.

### B2. Үнэ тооцох
- [x] **Тогтмол зардал (сав баглаа + карго) нэмэх** — `0021_fixed_cost.sql`,
      `settings.pricing.fixedCost` (одоогоор 0 — клиентээс тоо ирээгүй),
      `calc.ts` (тоймлохоос өмнө нэмнэ), `recompute_variant_prices()`,
      Тохиргоо хуудсанд глобал талбар + хэмжээ тус бүрд нь өөр утга (шатлалын
      мөрөнд хоосон орхивол глобалыг өвлөнө), барааны үнийн тооцоологч дээр
      харагдана. Сервер тал үргэлж `settings`-ээс уншина (браузер өөрөө
      тогтмол зардал тогтоож чадахгүй).

### B3. Бараа
- [x] **Админаас барааны зураг оруулах** — `product-images.tsx` компонент +
      `/api/admin/products/[id]/images` (POST / PATCH / DELETE). Байхгүй
      бараанд (шинээр үүсгэх үед) зургийг түр хавтсанд хийгээд үүсгэх үед нь
      холбоно. Мөн `/api/upload`-ын `folder` талбарыг хатууруулав — өмнө нь
      ямар ч нэвтэрсэн хэрэглэгч барааны хавтас руу зураг тавих боломжтой
      байсан (service role RLS-ийг алгасдаг).
      UX: файлаа чирж оруулах бүс (dragover үед тодрох) эсвэл дарж сонгох,
      ачаалж буй зураг тус бүрд орон зай, алдаа файл тус бүрээр (хаах
      товчтой), тоолуур `n / 12`. **Эрэмбийг чирж солино** — pointer event
      дээр суурилсан тул хуруугаар ч ажиллана, гар дээрээс сум товчоор ч
      болно. Эхний зураг «Үндсэн зураг» тэмдэгтэй.
- [x] **Дэлгэрэнгүй тайлбарыг 4 хэсэг болгох** — `0022_description_sections.sql`
      (`notes_description` / `usage_description` / `short_description`,
      `description` нь ерөнхий танилцуулга хэвээр). Админд `description-fields.tsx`
      (2 маягтад нийтлэг, тус бүрдээ жишээтэй), барааны хуудсанд тусад нь
      accordion — хоосон хэсэг харагдахгүй. Товч тайлбар нь гарчгийн доор ба
      meta description-д ашиглагдана.
- [x] **Бараа засварлах үед ml багц идэвх + override үнэ засах** — засварлах
      маягтад «Хэмжээ тус бүрийн үнэ» хүснэгт: авто үнэ, гар үнэ (override),
      эцсийн үнэ, «Зарна» чагт. Өмнө нь хэмжээ бүрийн үнэ **огт харагддаггүй**
      байсан. PATCH нь `variants`-ыг хүлээж авна (авто үнийг дахин бодсоны
      дараа хэрэглэнэ). Шинэ хэмжээ нэмэх нь Тохиргоо хуудсанд хэвээр.
- [x] **Sample (2ml) идэвхжүүлэх** — `0026_sample_tier.sql` нь `settings.pricing`-д
      2ml шатлалыг (коэф. 1.6) нэмнэ. Sample нь тусдаа үнийн жагсаалт биш —
      ердийн variant бөгөөд `ml === 2` нь мөрийг sample гэж тэмдэглэнэ
      (`SAMPLE_ML`). Барааны `sample_available` чагт авбал 2ml дэлгүүрт
      харагдахгүй (variant нь үнээ хадгалсан хэвээр үлдэнэ). Сервер тал
      `isSample`-ыг variant-аас өөрөө тооцно — браузарын хэлснийг авахгүй.
      Барааны хуудсанд 2ml дээр «Sample» тэмдэг, шинэ бараа үүсгэх маягтад
      чагт, нүүрийн Sample CTA нь `/catalog?ml=2` руу заана.
